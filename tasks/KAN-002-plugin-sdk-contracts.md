# KAN-002 — Контракты Plugin SDK

## Цель

Реализовать публичные типы, схемы и валидаторы Plugin Contract v1, не зависящие от внутренностей ядра.

## Результат

Плагин может импортировать `@kanbaner/plugin-sdk`, описать манифест, команду, запрос, событие, ресурс и UI-вклад, а также получить типизированный контекст выполнения.

## Объём работ

- [ ] Определить типы Plugin ID, версий и манифеста.
- [ ] Добавить валидацию манифеста.
- [ ] Определить метаданные команд и запросов.
- [ ] Определить JSON Schema-поля входа и выхода.
- [ ] Использовать TypeBox 0.34 как источник типов и JSON Schema.
- [ ] Использовать Ajv 8.20 для runtime-валидации.
- [ ] Определить метаданные событий и подписок.
- [ ] Реализовать разбор и валидацию `ResourceRef`.
- [ ] Определить типы `relation` и операций связей.
- [ ] Определить контекст выполнения.
- [ ] Определить единый конверт результата и коды ошибок.
- [ ] Определить метаданные экспорта в HTTP и MCP.
- [ ] Определить типы UI-вкладов без React-зависимости.
- [ ] Экспортировать публичные точки входа пакета.
- [ ] Добавить unit-тесты валидных и невалидных контрактов.

## Владение файлами

Разрешено:

- `packages/plugin-sdk/**`.

Запрещено:

- `packages/kernel/**`;
- `apps/web/**`;
- `specs/**`;
- `tasks/**`, кроме собственного отчёта;
- реализация runtime, БД или React-компонентов.

Общие файлы:

- Корневой `package.json` и lock-файл изменяются только по координации с оркестратором.

## Контракты и зависимости

- Реализует типы из `specs/plugin-contract.md`.
- Использует TypeBox 0.34 и Ajv 8.20 согласно `specs/technology-stack.md`.
- Не зависит от `@kanbaner/kernel`.
- Может использовать небольшую библиотеку JSON Schema-валидации после проверки документации.
- Не фиксирует поведение конкретного плагина.

## Критерии приёмки

- [ ] Манифест без обязательного поля отклоняется с понятной ошибкой.
- [ ] Некорректный Plugin ID отклоняется.
- [ ] `ResourceRef` корректно разбирается и отвергает неверный формат.
- [ ] Метаданные команды и запроса различают mutation и query.
- [ ] Экспорт по умолчанию выключен.
- [ ] Ошибки содержат стабильный код и признак `retryable`.
- [ ] JSON Schema генерируется из TypeBox без ручного дублирования.
- [ ] Ajv валидирует команды, запросы и ответы по сгенерированным схемам.
- [ ] Публичный API SDK не импортирует код ядра.
- [ ] Пакет собирается как самостоятельный модуль.
- [ ] Тесты покрывают успешные и ошибочные сценарии.

## Проверки

- [ ] Typecheck.
- [ ] Линтер.
- [ ] Unit-тесты пакета.
- [ ] Проверка экспортов пакета.
- [ ] Проверка отсутствия импортов из `kernel` и `apps`.

## Риски

- Слишком широкий SDK до появления реальных плагинов. Реализовать только Contract v1.
- Дублирование JSON Schema и TypeScript-типов. Использовать TypeBox как единый источник и Ajv для runtime-проверки.
- Связать SDK с фреймворком UI. Держать типы UI-вкладов независимыми от React.
