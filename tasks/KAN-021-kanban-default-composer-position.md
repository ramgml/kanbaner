# KAN-021 — Канбан по умолчанию и composer под заголовком

## Цель

Упростить повседневную работу с доской: открывать канбан при отсутствии
сохранённого представления и держать создание карточки в начале каждой колонки.

## Результат

- Вход в рабочее пространство без сохранённого представления открывает канбан.
- Выбор `Список / Канбан` по-прежнему сохраняется в
  `kanbaner.projects.lastView` и восстанавливается после reload.
- Неизвестное значение или ошибка localStorage приводят к канбану без ошибки UI.
- `+ Добавить карточку` и composer находятся сразу под заголовком колонки;
  нижней кнопки создания нет.
- Создание проектов, тема, домен и операции задач не меняются.

## Критерии приёмки

- [ ] Отсутствие, неизвестное значение и ошибка чтения localStorage дают канбан.
- [ ] Сохранённый список и сохранённый канбан восстанавливаются после reload.
- [ ] Смена проекта не сбрасывает выбранное представление.
- [ ] Composer расположен под заголовком колонки и не требует прокрутки карточек.
- [ ] Создание проектов работает без изменений.
- [ ] Все проверки зелёные.

## Риски

- Перенос composer может изменить вертикальный layout длинных колонок.
  Смягчение: composer остаётся вне прокручиваемой области, список сохраняет
  собственный scroll.
- Старые E2E могут ожидать обзор при пустом localStorage. Смягчение: явно
  обновить входные сценарии и проверить оба сохранённых представления.
