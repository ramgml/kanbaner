# KAN-019 — Рабочее пространство проектов

## Цель

Объединить пользовательские представления в один плагин `kanbaner.projects`:
переключение проектов в sidebar, канбан конкретного проекта, список задач,
переключатель представления и создание карточки только по названию.

Домен `kanbaner.tasks`, хранение и публичные команды не меняются. Отключение
UI-плагина не влияет на данные и API.

## Результат

- Sidebar содержит проекты с поиском, выбором и созданием, а не постоянные
  пункты администрирования.
- Канбан всегда принадлежит одному проекту. Агрегированная доска всех проектов
  и бейдж проекта на карточках удалены.
- Заголовок проекта содержит переключатель `Список / Канбан` с сохранением
  проекта, фильтров и выбранной задачи.
- Создание карточки требует только название; проект определяется доской,
  статус — колонкой, полная форма открывается только для редактирования.
- Текущие Trello-доска, модал, composer, список и сводки продолжают работать в
  одном UI-плагине.

## Объём работ

- [ ] Объединить UI entrypoint и metadata в один плагин. Сохранить маршруты

- [ ] Обновить `apps/web/src/ui/builtin-ui-plugins.ts`, build:packages,
  dependencies, lock и import boundaries.
- [ ] Обновить package layout в `specs/architecture.md`: domain tasks отделён
  от UI projects.

### Переключение проектов в sidebar

- [ ] Добавить секцию «Проекты» в `app.sidebar` только на project-related
  маршрутах.
- [ ] Список: активный проект, поиск при большом количестве, scroll внутри
  sidebar, доступные кнопки и `aria-current`.
- [ ] Выбор проекта меняет `?project=<id>` без промежуточного экрана и
  запоминает последний выбор.
- [ ] Кнопка `+` создаёт проект по минимальной форме и сразу открывает его.

- [ ] Не показывать секцию в настройках/plugin manager.

### Одна доска одного проекта

  проекта и повторный project selector внутри доски.
- [ ] Сохранить экран/режим проектов со сводками только если он используется
  как необязательный обзор, не как обязательный путь переключения.
- [ ] Заголовок проекта использует `project.summary`, описание и точные
  счётчики выбранного проекта.

### Переключатель представления

- [ ] В заголовке проекта `Список / Канбан` с `aria-pressed` и клавиатурной
  навигацией.
- [ ] Переключение использует `/view/tasks` и `/view/kanban`, сохраняет
  `project`, фильтры и выбранную карточку.
- [ ] Последнее представление запоминается; список может сохранять свой

### Создание только по названию

- [ ] Общая кнопка «Новая задача» открывает короткий composer с одной строкой

- [ ] Поле проекта убрано из всех composer: оно определяется доской.
- [ ] Статус определяется колонкой, позиция — доменным append. Полная форма
  используется только для редактирования.
- [ ] Убрать отдельный путь «Добавить с деталями» из composer; подробности
  заполняются после открытия карточки.
- [ ] Сохранить double-submit guard, ошибки без потери ввода, фокус, Escape и
  появление карточки за page boundary.

## Владение файлами

Разрешено:

- `packages/plugin-projects/**`;
- `packages/plugin-kanban/**` и `packages/plugin-task-list/**` — только
  перенос/удаление устаревших файлов;
- `packages/task-ui/**` — additive общие примитивы;
- `apps/web/src/ui/builtin-ui-plugins.ts`;
- `apps/web/package.json`, корневой `package.json`, `pnpm-lock.yaml`;
- `apps/web/e2e/kanban.spec.ts`, `apps/web/e2e/task-list.spec.ts`,
  `apps/web/e2e/test-environment.ts`;
- `scripts/check-import-boundaries.mjs`;
- `tests/contract/task-list-disabled.test.ts` — переименование UI plugin ID;
- `specs/architecture.md` — только package layout;
- `tasks/reports/KAN-019.md`.

Запрещено:

- `packages/kernel/**`, `packages/plugin-sdk/**`, `packages/storage-sqlite/**`;
- `packages/plugin-tasks/src/**` — доменные изменения не требуются;
- остальные `apps/web/src/**` без отдельного согласования;
- `specs/plugin-contract.md`, другие плагины и задачи.

Общие файлы:

- `packages/task-ui` остаётся общей библиотекой, не становится плагином.
- Переносимый код должен сохранить прежние проверки и стабильные selectors.

## Контракты и зависимости

- Зависит от KAN-010…KAN-018.
- Новый UI-контракт `kanbaner.projects.ui.v1`.
- Использует только публичные `kanbaner.tasks` commands/queries.
- Не меняет данные, миграции и доменные схемы.
- Блокирует KAN-020.

## Критерии приёмки

- [ ] Проекты переключаются в sidebar без отдельного экрана.
- [ ] Канбан всегда показывает конкретный проект, нет агрегированной доски.
- [ ] `Список / Канбан` переключает представления без потери контекста.
- [ ] Для создания карточки требуется только название.
- [ ] В production активен один UI-плагин проектов вместо двух старых.
- [ ] Отключение UI-плагина не влияет на данные и API.
- [ ] Все проверки зелёные.

## Проверки

- [ ] Typecheck, линтер, component/integration tests.
- [ ] `pnpm check:imports`, полный `pnpm check`.
- [ ] Все Playwright E2E, deferred SIGTERM.

## Риски

- Большой перенос может потерять часть старого поведения. Смягчение: перенос
  тестов вместе с кодом и сохранение routes/test IDs.
- Sidebar может быть перегружен большим числом проектов. Смягчение: поиск,
  внутренний scroll и последний активный проект.
- Удаление старых plugin ID меняет состав plugin manager, но не данные. Это
  фиксируется в отчёте и проверяется отключением.
