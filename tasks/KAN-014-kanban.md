# KAN-014 — Канбан

## Цель

Создать отдельный UI-плагин `kanbaner.kanban` с четырьмя фиксированными
колонками, перемещением карточек между статусами и изменением порядка.
Канбан использует тот же домен `kanbaner.tasks` и не содержит собственной
копии задач.

## Результат

- На `/view/kanban` открывается доска с колонками `Backlog`, `To do`,
  `In progress`, `Done`.
- Карточка показывает заголовок, приоритет, срок, теги и число подзадач.
- Перемещение доступно drag-and-drop и через меню/кнопки для клавиатуры и
  мобильных.
- Изменение оптимистично; при ошибке карточка возвращается, конфликт версий
  показывается без перезаписи.
- Порядок карточек сохраняется и переживает перезапуск.
- На мобильных колонки прокручиваются горизонтально.

## Объём работ

### Плагин канбана

- [ ] Создать `packages/plugin-kanban`: manifest, `server` entrypoint без
      доменной логики, `ui` entrypoint.
- [ ] Manifest: `requires: { "kanbaner.tasks": "^1.0.0" }`, permissions
      `commands`, `events`, `ui`, `provides: ["kanbaner.kanban.ui.v1"]`,
      `consumes: ["kanbaner.tasks.commands.v1", "kanbaner.tasks.queries.v1"]`.
- [ ] Зарегистрировать вклад `kind: "view"`, `slot: "app.main"`,
      `route: "/view/kanban"`.
- [ ] Зарегистрировать навигационный вклад в `app.sidebar`.
- [ ] Зарегистрировать детали/редактор задачи в `app.overlays` через
      `packages/task-ui`, чтобы не зависеть от `kanbaner.task-list`.
      Overlay рендерится только при активном `/view/kanban`, выбранной
      карточке и открытом локальном состоянии; на других маршрутах вклад
      не показывается.

### Доска

- [ ] Четыре фиксированные колонки в порядке `backlog`, `todo`,
      `in_progress`, `done`.
- [ ] Заголовок колонки, количество задач и пустое состояние.
- [ ] Карточка: заголовок, приоритет, срок, теги, число подзадач, индикатор
      конфликта.
- [ ] Загрузка задач через `kanbaner.tasks.task.list` с фильтрами по проекту и
      тегу и сортировкой по позиции.
- [ ] Пагинация или догрузка внутри колонки; не терять порядок.
- [ ] Фильтр по проекту и тегу, сохранение в query string.
- [ ] Горизонтальная прокрутка колонок на мобильных без горизонтального
      скролла всей страницы.

### Перемещение и порядок

- [ ] Перемещение вызывает `kanbaner.tasks.task.move` с `expectedVersion`,
      целевым статусом и позицией.
- [ ] При переходе в `done` выставляется `completedAt`; при выходе — очищается.
- [ ] Drag-and-drop работает на десктопе и реализован нативными
      pointer/mouse events. Новую DnD-библиотеку не добавлять без
      согласования.
- [ ] Меню «Переместить в…» и кнопки «Вверх/вниз» доступны с клавиатуры и на
      мобильных.
- [ ] Оптимистичное обновление: карточка сразу меняет колонку/место; при ошибке
      возвращается и показывается сообщение.
- [ ] `VERSION_CONFLICT` обновляет доску и не перезаписывает чужие изменения.
- [ ] Во время запроса блокируется только затронутая карточка, не вся доска.

### UI-рантайм и интеграция

- [ ] Использовать `invoke` из UI-рантайма KAN-013; не импортировать server
      actions, базу и внутренние модули `apps/web`.
- [ ] Добавить регистрацию канбана в `apps/web/src/ui/builtin-ui-plugins.ts` по
      согласованию с KAN-013.
- [ ] Использовать `packages/task-ui` для карточки, редактора и общих
      состояний. Не дублировать детали задачи.
- [ ] Типы операций, ID и схемы брать только из
      `@kanbaner/plugin-tasks/contract`, не из корневого серверного
      entrypoint.
- [ ] Отключение канбана не влияет на задачи, список и API.

### Проверки

- [ ] Component-тесты колонок, карточек, меню перемещения и оптимистичного
      отката.
- [ ] Integration-тест регистрации вкладов и маршрута `/view/kanban`.
- [ ] E2E на production custom server с изолированной БД:
  - создать проект и задачи через список/API;
  - увидеть их в правильных колонках;
  - переместить карточку drag-and-drop;
  - переместить через меню с клавиатуры;
  - изменить порядок и перезагрузить страницу;
  - получить конфликт версий и убедиться в откате;
  - проверить мобильную горизонтальную прокрутку 360 px.
- [ ] Проверить, что канбан и список показывают согласованные данные после
      команды в любом представлении.

## Контракты и зависимости

- Зависит от `kanbaner.tasks` (KAN-012) и UI-рантайма KAN-013.
- Новые контракты: UI-вклад `kanbaner.kanban.ui.v1`, маршрут `/view/kanban`.
- Использует команду `kanbaner.tasks.task.move` и запрос
  `kanbaner.tasks.task.list` через `@kanbaner/plugin-tasks/contract`.
- Не зависит от `kanbaner.task-list` в рантайме: детали рендерятся через
  общий `packages/task-ui`.

## Критерии приёмки

- [ ] Доска показывает четыре фиксированные колонки и корректные задачи.
- [ ] Перемещение меняет статус, позицию, версию и `completedAt`.
- [ ] Drag-and-drop не является единственным способом перемещения.
- [ ] Основные действия доступны с клавиатуры.
- [ ] Ошибка или конфликт возвращает карточку и не теряет данные.

- [ ] На 360 px колонки прокручиваются горизонтально, страница — нет.
- [ ] Overlay деталей не появляется вне `/view/kanban` и без выбранной карточки.
- [ ] DnD не является единственным способом перемещения и не требует новой
      библиотеки.
- [ ] Канбан не содержит доменной логики и не импортирует внутренности
      `kanbaner.tasks`.
- [ ] Отключение канбана не влияет на данные и другие представления.
- [ ] Нет второй component library.

## Риски

- Drag-and-drop сложно сделать доступным. Смягчение: меню и кнопки — основной
  путь, DnD — дополнительный.
- Оптимистичное обновление может рассинхронизировать доску. Смягчение: откат
  по ошибке и повторный запрос после конфликта.
- Горизонтальная прокрутка на мобильных конфликтует со свайпами страницы.
  Смягчение: прокрутка только внутри контейнера колонок.
- Общий `task-ui` может разрастись. Смягчение: только переиспользуемые
  компоненты задач, без доменных запросов внутри библиотеки.
