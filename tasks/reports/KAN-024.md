## Что сделано

### Доска и данные

- `KanbanView` строит доску только из `kanbaner.tasks.column.list`: порядок
  `position asc, id asc`, без `TASK_STATUSES`. Каждая колонка получает задачи
  через `task.list{columnId, projectId, tag}` с собственной пагинацией
  `offset/nextOffset` и сохранением порядка.
- Новый проект показывает три default-колонки `ToDo`, `In Progress`, `Done`.
  Legacy-проект сохраняет `Backlog`, `To do`, `In progress`, `Done`; Backlog
  снова виден после доменного backfill/ленивой материализации.
- `task.create`, `task.move` и `task.complete` используют `columnId`; legacy
  `status` остаётся совместимым зеркалом и derived-полем, а не источником UI.
- Позиции задач и колонок сохраняются после reload: `task.move` считает
  позицию по полному scope `(projectId, columnId)`, `column.move` — по
  позиции колонки в проекте.
- Добавлена стабильная схема test ID: канонические default/legacy-колонки
  сохраняют суффиксы `todo`, `in_progress`, `done`, `backlog`; пользовательские
  колонки получают безопасный суффикс `column-<id>`.

### Управление колонками

- `+ Добавить колонку` после последней колонки: название, тип `open`/`Done`,
  append по умолчанию. Есть autofocus, Escape, guard от двойной отправки и
  сохранение ввода при ошибке.
- Меню заголовка: переименование, `Переместить влево/вправо`, удаление.
  Переименование использует `column.update` с `expectedVersion`, сохраняет
  ввод при ошибке и показывает конфликт.
- Reorder: drag handle заголовка (реальный pointer DnD), кнопки влево/вправо
  доступны с клавиатуры и на мобильном. Оптимистичный порядок откатывается при
  ошибке; `VERSION_CONFLICT` перечитывает фактический порядок и показывает
  конфликт.
- Удаление — destructive-диалог с `confirm: true`, явным `targetColumnId`,
  количеством переносимых задач и последствиями `completedAt`. Целевой список
  строится только из колонок проекта и исключает удаляемую; последняя открытая
  или последняя Done-колонка недоступна для удаления. После успеха
  перечитываются задачи, колонки и сводка.
- Поддержаны несколько Done-колонок; перенос в Done проставляет `completedAt`,
  перенос в open-колонку снимает его.

### Карточка, список и заголовок

- Create/quick composer под заголовком колонки передают `columnId`; полная
  форма остаётся только для редактирования.
- В Trello-модале быстрые поля статуса заменены фактическими колонками:
  `nextColumnId`, выбор колонки подзадачи, бейджи подзадач по заголовкам,
  «Завершить» скрывается для Done-колонки. Быстрые черновики, конфликты,
  rebase/keep-local и draft guard сохранены.
- `TaskDetails`/`TaskTable`/`TaskCard` показывают фактическую колонку, если
  передан список `columns`; legacy-статус остаётся fallback.
- `TaskFilters` получил фильтр фактической колонки (`?column=<id>`), статусный
  фильтр заменён. Заголовок доски показывает `Всего`, `Просрочено` и счётчики
  фактических колонок, без навязывания четырёх фиксированных статусов.
- Старая ссылка `?status=backlog` поддержана как публичный legacy-путь:
  показывается предупреждение, новые задачи создаются через legacy `status` и
  лениво материализуют Backlog-колонку домена. Прямого доступа к SQLite нет.

### Исправления по ходу проверок

- `isLastColumnOfType` сравнивает тип `open/done`, а не точный legacy-статус.
- Мобильная доска после full navigation детерминированно сбрасывает
  горизонтальный scroll и делает активной первую фактическую колонку; это
  убрало зависимость `aria-selected` от восстановленного браузером scroll.
- `TaskCard` на мобильном показывает фактический заголовок колонки, а не
  legacy-метку.
- E2E drag-to-top использует точку внутри нового заголовка (высота изменилась
  из-за меню колонки), а меню колонки ищется только в `header`, не задевая
  меню карточек.

## Исправления по findings ревью

- **HIGH 1 — project isolation.** `KanbanView` хранит `loadedProjectId`;
  `boardReady`/`boardColumns` не показывают A после выбора B до успешного
  `column.list B`. Переключение очищает placements/pending/conflicts/drag/
  visibility/active/menu/forms. Все task/column handlers, включая delete
  target и DnD, проверяют `projectId === effectiveProjectId`. Deferred-тест
  проверяет скрытие A, disabled create/add и появление B.
- **HIGH 2 — `?column=`.** `TaskListView` хранит `columnsProjectId` и
  `columnsErrorProjectId`; loading/ready/activeColumns производные. Фильтр
  валидируется только после успешной загрузки текущего проекта, при непустом
  списке. Тесты: deferred, error, empty, legacy status, reset и back/forward.
- **HIGH 3 — exact delete count.** Диалог читает
  `task.list{projectId,columnId,limit:1}` без tag, блокирует confirm до
  успеха, показывает ошибку счётчика отдельно, перепроверяет счётчик перед
  командой. Тесты: скрытая тегом задача, deferred count, ошибка count.
- **HIGH 4.** `query.legacyStatus` добавлен в зависимости эффекта `task.list`;
  покрыты reset и back/forward.
- **HIGH 5.** Legacy composer имеет один destination: подпись берётся из
  фактической колонки статуса либо `Backlog/To do/In progress/Done`, payload —
  legacy `status` без `columnId`. Тест проверяет `Backlog` и payload.
- **HIGH 6.** Rename/move/delete ждут `refreshProjectColumns`; pending не
  снимается до refresh, success-notice только после свежего списка, refresh
  error отдельный. Конфликт обновляет локальную версию, повторная отправка
  использует свежие `expectedVersion` и пересчитанный `targetColumnId`.
  Добавлены deferred/conflict тесты reorder, rename и delete.
- **HIGH 7.** Test doubles определяют статус только через lookup `TaskColumn`;
  парсинг ID удалён. Для move/create добавлены проверки зеркала
  `status/columnId`.
- **HIGH 8.** Добавлен реальный pointer E2E: перетаскивание колонки
  left/right/no-op, persist после reload и drop карточки на header без
  изменения порядка колонок.

## Исправления повторного ревью

- **In-flight project switch.** Добавлены `effectiveProjectIdRef` и
  `projectGenerationRef`; после каждого awaited read перед task/column
  create/move/update/delete проверяется актуальность generation/project. При
  смене проекта команда не отправляется, optimistic placement/pending
  отменяется, pointer listeners снимаются. Delete дополнительно проверяет
  request/source/target диалога. Регрессии: deferred `fetchAllScopeTasks` A→B —
  `task.move` отсутствует; deferred delete revalidation A→B — `column.delete`
  отсутствует.
- **Delete count revalidation.** Если fresh total отличается от
  подтверждённого, команда не отправляется: показывается новое число и
  сообщение «Последствия изменились…», confirm снова доступен; повторный
  confirm выполняет удаление. Проверяются project/source/target.
- **New column loading.** После успешного `column.create` вызывается полный
  `reloadBoard`, поэтому empty state новой колонки появляется без внешнего
  reload. При ошибке refresh сообщение предлагает повторить загрузку, а не
  создание. Добавлен component test.
- **Optimistic reorder.** Перед update сохраняется snapshot порядка; при любой
  ошибке команды snapshot восстанавливается немедленно, независимо от refresh.
  Ошибка refresh не перетирает основную ошибку команды. При конфликте и
  неудачном refresh доска скрывается как недоверенная. Добавлены тесты
  failed command + failed refresh и conflict + failed refresh.

## Отклонения и ограничения

- `project.summary` по-прежнему отдаёт счётчики по четырём legacy-статусам:
  это контракт KAN-023. Доска/заголовок используют фактические колонки, а
  обзор проектов сохраняет status-разбивку как derived-совместимость.
- Позиция колонки в `column.move` — индекс вставки в итоговом порядке, а не
  абсолютная позиция документа; UI передаёт индекс и после команды
  перечитывает порядок.
- Legacy-ссылка `?status=` не является основным фильтром: она нужна для
  старых закладок и проверки ленивой материализации Backlog. Основной фильтр —
  `?column=`.
- События колонок и перенесённых задач остаются best-effort по контракту
  KAN-023; UI после команды всегда перечитывает состояние.
- E2E проверяют desktop 1440×900 и mobile 360×740 в Chromium.
