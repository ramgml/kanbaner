# KAN-064 — История и управление OpenCode-сессиями

Дата: 2026-11-24. Реализация: worktree
`.worktrees/kan-064-session-history`, ветка `feat/kan-064-session-history` от
`dev`. Push/merge/rebase/amend не выполнялись.

## Результат

- Добавлен `GET /api/opencode/session` — внутренний same-origin UI transport
  списка последних сессий. Query-параметры не принимаются: cursor, directory,
  project и limit от браузера игнорируются с `VALIDATION_ERROR`. Ответ —
  успешный envelope с массивом whitelist-записей `{id, title, updatedAt}`.
- Добавлен `PATCH /api/opencode/session/{sessionID}` — явное переименование
  текущей сессии. Body — строгий JSON-объект ровно с одним строковым полем
  `title` (до 4 KiB). `metadata`, `permissions`, `archived` и другие поля не
  принимаются и не отправляются.
- Gateway `listSessions()` ограничен: не больше 4 upstream-страниц
  `session.list` по `limit: 50`, остановка по `next` или повторному cursor,
  дедупликация ID, сортировка по `time.updated` desc с устойчивым tie-break по
  ID и максимум 30 записей в ответе. N+1 без границы и бесконечная pagination
  исключены.
- В список попадают только разрешённые root-сессии (`parentID: null`)
  `metadata.source=kanbaner`, агента `kanbaner`, с валидным `time.updated`,
  без `time.archived` и с тем же нормализованным project directory. Чужие,
  архивные, child/subagent-сессии и другие проекты отбрасываются до ответа.
- Ownership ужесточён для чтения, prompt, model switch и rename: чужая,
  child или сессия другого проекта неотличима от отсутствующей (`NOT_FOUND`).
- Наружу не попадают `metadata`, `location`, `projectID`, стоимость, токены,
  permissions, model, agent, outcome, `archived` и `subpath`.
- `renameSession()` валидирует заголовок до ownership-запроса: NUL/C0/C1
  запрещены, пробелы схлопываются, допускается 1–100 code points. Upstream
  получает только `{sessionID, title}`; `metadata` не заменяется. Ответ —
  `{id, title}` после проверки ownership.
- В шапке панели показывается заголовок текущей сессии и кнопка
  «Переименовать сессию». Форма rename: `Enter`/«Сохранить» отправляет,
  `Escape`/«Отмена» закрывает и возвращает фокус кнопке; `Escape` не всплывает
  до закрытия всей панели.
- История — нативный `<details>` под шапкой. Она загружается лениво только при
  раскрытии и кэшируется на 30 секунд. Создание сессии, завершённый prompt и
  rename инвалидируют кэш; раскрытая история перезагружается сразу.
- Выбор записи — guarded GET точной сессии в отдельной generation-операции.
  `404` удаляет только недоступную запись и не меняет текущую сессию или
  сохранённый ID; `503` показывает «Не удалось открыть сессию» и кнопку
  повтора. Stale list/switch response отбрасывается по generation.
- Во время prompt, rename и model switch записи истории и форма rename
  заблокированы. Переключение сохраняет per-session черновик KAN-063 и
  восстанавливает canonical messages, model и draft целевой сессии.
- Reload сохранённого ID с `404` очищает только `localStorage` ID и показывает
  empty state с кнопкой «Новая сессия» без автоматического `POST`. Временный
  `503` сохраняет ID и текущую сессию. Режим bootstrap без сохранённого ID не
  изменён.
- Поведение scroll/unread/focus, stable turn/admission/canonical semantics,
  compact tools, вложения и redaction не менялись. Все прежние E2E-сценарии
  остались зелёными.

## Ограничения bound

- Список: максимум `4 × 50` upstream-сессий просматривается на один запрос,
  клиенту отдаётся максимум 30 записей. Более старые сессии за пределами
  четырёх страниц в интерфейсе не появляются.
- Пагинация не принимается от браузера; повторный cursor обрывает цикл и
  предотвращает зацикливание upstream.
- Заголовок ограничен 100 code points (не байтами и не UTF-16 units).
