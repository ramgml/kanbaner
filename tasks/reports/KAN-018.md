# KAN-018 — Проекты как доски и сводки

## Итог

Реализовано Trello-like отображение проектов и additive публичный запрос
`kanbaner.tasks.project.summary`. Счётчики считаются по полному набору задач
проекта в Store, а не по странице карточек. Заголовок доски и сетка проектов
используют одну и ту же сводку; после create/move/complete/delete/update due
она перечитывается.

## Контракт

- Новый query ID: `kanbaner.tasks.project.summary`.
- Вход: `{ projectId?, limit?, offset? }`, `limit` 1…200, по умолчанию 50.
- Выход: `{ items, total, nextOffset, totals }`.
  - `items[]`: `{ project, total, counts: { backlog, todo, in_progress, done },
overdueCount }`;
  - `totals`: те же агрегаты без проекта, по **всем** подходящим проектам.
- Схемы и типы добавлены в `packages/plugin-tasks/src/schemas/queries.ts`
  (client-safe contract). Существующие команды и схемы не изменялись.
- Метаданные: `kind = query`, `risk = read`; activation проставляет
  `exposure = { ui: true, http: false, mcp: false }`.
- Явный несуществующий `projectId` → `NOT_FOUND` (entity `project`).

## Store и просроченность

- `TasksStore.summarizeProjects` добавлен аддитивно (root и transaction-scoped).
- Store читает проекты и задачи документами пачками по 1000, агрегирует одним
  проходом; при явном `projectId` читает только его scope. SQL, имена таблиц и
  N+1 отсутствуют.
- `totals` и счётчики считаются по полному набору данных, пагинация влияет
  только на `items`/`total`/`nextOffset` страницы проектов.
- Просроченность: `status !== "done" && dueAt !== null &&
compareUtcTimestamps(dueAt, observedAt) < 0`, где `observedAt` берётся из
  injected `now`-источника Store. `dueAt == now` не просрочено; дробные UTC
  сравниваются без `Date.parse`.

## UI

- На `/view/kanban` появился доступный режим «Доска» / «Проекты»
  (`kanban-mode-board`, `kanban-mode-projects`, `aria-pressed`).
- Сетка `kanban-projects`: карточки с названием, описанием, общим числом задач,
  счётчиками по четырём статусам и просроченными.
  - Карточка открывает канбан проекта (`project` в query string).
  - «Открыть список» ведёт на `/view/tasks?project=<id>`.
  - Проекты читаются страницами по 12 с кнопкой «Показать ещё» без потери уже
    загруженных карточек.
  - Пустое состояние предлагает создать первый проект через существующую
    `ProjectForm`.
- Заголовок доски показывает `kanban-board-summary`:
  - выбранный проект — его `total/counts/overdue`;
  - «Все проекты» — агрегат `totals` по всем проектам.
- Обновление сводки: `project.create` и `task.move` вызывают повторный
  `project.summary`; create/complete/delete/update due идут через локальную
  ревизию, на которую подписаны оба запроса сводки.
- Ошибка сводки не скрывает доску: колонки продолжают работать.

### Исправления по ревью

- **Stale summary race (MEDIUM).** `loadSelectedSummary` читает актуальный
  `projectId` из `selectedProjectIdRef` на момент запуска, а не из замыкания.
  Смена проекта инкрементирует sequence, поэтому ответы прежнего проекта
  игнорируются. Дополнительно `activeSelectedSummary` допускает сводку в
  заголовок только при `selectedSummary.project.id === query.projectId`.
- **Проекты за пределами первых 200 (MEDIUM).** `selectedProject` и заголовок
  берутся из `activeSelectedSummary.project`, если проекта нет в первой
  странице `project.list`. `projectOptions` добавляет выбранный проект в
  селект фильтра и формы, даже когда его нет среди первых 200.
- **Scoped summary (LOW).** Добавлены тесты `store.withTransaction`, которые
  создают проект и задачи и читают `scoped.summarizeProjects` внутри той же
  транзакции на in-memory и SQLite: видны данные текущей транзакции,
  `totals` полные, неизвестный проект → `NOT_FOUND`; корневые тесты сохранены.
- **Update due E2E (LOW).** Сценарий future → past → future проверяет
  `kanban-summary-overdue` в заголовке и overdue на карточке сетки после
  каждой команды.
- **E2E-файл после merge.** При объединении сценариев KAN-017/KAN-018 был
  потерян закрывающий `});` одного теста; синтаксис восстановлен, все прежние
  сценарии сохранены.

## Ограничения и риски

- Агрегация читает все документы задач проекта (пачками), что приемлемо для
  локальной однопользовательской установки; отдельная денормализация счётчиков
  не вводилась. При росте данных оптимизация — отдельной задачей.
- Сводка обновляется после команд, но не подписывается на события из другого
  клиента/вкладки; при внешнем изменении нужен reload или следующая команда.
- Кнопка `kanban-create-task` рендерится в шапке независимо от режима, поэтому
  создать задачу можно и на доске, и в режиме «Проекты». В сетке проектов
  дополнительно есть пустое состояние с отдельной кнопкой
  `kanban-projects-create-first`, ведущей в ту же `ProjectForm`.
- E2E пустого состояния опирается на порядок тестов при `workers: 1` и пустой
  каталог данных прогона; это отмечено комментарием в тесте.
- E2E считает сумму карточек после догрузки всех страниц и сравнивает с
  агрегатом; при >20 страницах сработал бы guard, но текущий набор данных
  укладывается с запасом.
