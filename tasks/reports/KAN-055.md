# KAN-055 — Файлы и список инструментов в OpenCode-панели

Дата начала: 2026-11-19. Дата последних проверок: 2026-11-21.

## Цель

Позволить пользователю прикреплять файлы к prompt OpenCode и заранее видеть,
какие операции доступны агенту.

## Результат

- В панель добавлен file picker для UTF-8 text/code, PNG/JPEG/GIF/WebP и PDF:
  до 5 файлов и 8 MiB суммарно, до 1 MiB на текстовый файл и до 5 MiB на
  image/PDF.
- Selection отображается chips с именем и размером; файлы можно удалить до
  отправки. Optimistic message и восстановленная history показывают `name` и
  `mime`, но не Base64 или содержимое.
- PNG/JPEG/GIF/WebP получают thumbnail в composer и preview в user message.
  Локальный File использует blob URL с revoke при remove/unmount и сохраняется
  при canonical refresh. После полной перезагрузки canonical image загружается
  повторно через guarded binary endpoint по exact session/message/index. History
  JSON остаётся metadata-only; при отсутствии валидного inline-источника
  отображается обычная карточка без broken image.
- Browser использует `FileReader` и отправляет `{name, mime, base64}`. Сервер
  проверяет canonical Base64, фактический размер, UTF-8 через fatal
  `TextDecoder`, сигнатуры изображений и `%PDF-`. В OpenCode передаются только
  inline `data:` URL с `source: {type: "inline"}`; `file:` URL и server paths
  запрещены.
- `FileReader` связан с AbortSignal и generation. Double-submit, add/remove во
  время подготовки, Stop и unmount не создают лишний prompt. Selection
  очищается только после terminal `done`; при pre-admission, NDJSON, abort и
  malformed-stream ошибках файлы остаются для retry.
- Раскрываемый catalog показывает 14 фактических MCP tools с именами
  `kanbaner_*`, `operationId`, `risk=read|write` и `requiresExpectedVersion`.
  Metadata сверена с реальным `client.listTools`; delete, shell и filesystem
  tools отсутствуют.
- По явному решению пользователя image/PDF при неподдержке моделью не
  блокируют prompt: панель предупреждает, а OpenCode/provider может заменить
  вложение служебной заметкой или отклонить его.

## Независимые проверки и исправления

Coding-агент реализовал основной срез: 42/42 focused tests и 3/3 E2E.
Независимый reviewer обнаружил гонку FileReader и преждевременную очистку
selection. Follow-up worker исправил их и добавил regressions для delayed
FileReader, double-submit, add/remove, Stop/unmount, pre-admission errors и
terminal done. Финальный reviewer подтвердил отсутствие оставшихся
blocker/high/medium.

Finding о блокировке image/PDF по model capabilities не применялся: оно
противоречило более позднему явному решению пользователя оставить только
предупреждение.

Для image preview отдельный reviewer подтвердил корректность локальных blob URL
и canonical matching. Добавление `@source` для `packages/opencode/src` исправило
отсутствие production-утилит размеров preview; OpenCode и shell E2E подтвердили
отсутствие регрессий.

При добавлении persistent preview reviewer обнаружил blocker: mock использовал
`file.uri`, тогда как canonical OpenCode 2.2.5 хранит raw Base64 в `file.data` с
`file.mime` и `source.type === "inline"`. Worker исправил production и fixtures,
а также строгое отклонение trailing newline в Base64 и attachment index.
Follow-up reviewer подтвердил закрытие blocker и обоих low-замечаний.
