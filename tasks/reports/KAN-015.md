## Что сделано

### Создание на доске

- В заголовке доски добавлены кнопки «Новый проект»
  (`kanban-create-project`) и «Новая задача» (`kanban-create-task`).
- В каждой колонке добавлена кнопка «+ Новая задача» с доступным именем
  `Новая задача в колонке «…»` (`kanban-create-task-<status>`). Кнопка
  скрывается вне `/view/kanban` и недоступна, пока нет проектов.
- Формы открываются только на `/view/kanban`.
  - Mobile: нативный `ModalDialog` из `@kanbaner/task-ui` — focus trap,
    Escape, возврат фокуса, breakpoint сохраняет открытый режим.
  - Desktop: inline-панель над колонками; Escape закрывает форму.
- Используются существующие `ProjectForm`, `TaskForm`, `ModalDialog`;
  `packages/task-ui` не изменялся, потому что текущего API достаточно.
- Новый компонент `src/ui/kanban-create.tsx` не содержит доменных запросов.

### Предустановки и команды

- Кнопка колонки предустанавливает `status`.
- Активный фильтр `project` подставляется в форму; без фильтра
  `projectId` пустой, проект нужно выбрать явно.
- Родитель необязателен; форма показывает только корневые задачи выбранного
  проекта. Список родителей читается `task.list` с `parentTaskId: null`.
- `project.create`: payload `{ title, descriptionMarkdown }`. После успеха
  выполняется повторный `project.list`, проект сразу появляется в фильтре и
  форме, текущий фильтр не сбрасывается.
- `task.create`: payload без `position` (домен делает атомарный append).
  Передаются project/title/description/status/priority/dueAt/tags и
  необязательный parent.
- После создания проекта форма закрывается. После создания задачи
  увеличивается локальная ревизия, доска перечитывается, а target-колонка
  догружается до созданного ID через существующий механизм
  `visibilityRef`/`mustIncludeIds`. Карточка видна даже за границей первой
  страницы.
- Если созданная задача не попадает в активный фильтр проекта или тега,
  фильтр меняется только в объёме, необходимом для её показа (например,
  сбрасывается несовпадающий тег).
- Отправка защищена `submitGuardRef` и `submitting`: двойной клик/Enter не
  создаёт дубликат. Кнопки disabled, у submit есть `aria-busy`.
- Ошибка остаётся внутри формы; введённые значения сохраняются.

## Ограничения и риски

- При активном фильтре, в который созданная задача не попадает, фильтр
  автоматически расширяется/сбрасывается в минимальном объёме. Это сознательное
  решение, чтобы созданная карточка была видна; альтернатива — оставить её
  скрытой.
- Список родителей ограничен `limit: 200`, как и в существующей форме списка;
  отдельного агрегата/поиска в контракте нет.
- Число подзадач обновляется по ревизии после создания; для карточек за
  границей страницы счётчик появится после их догрузки.
- Component-тесты используют stub `matchMedia`; реальная геометрия и focus trap
  проверяются Playwright в Chromium.
- Тесты работают на общей E2E-базе и используют уникальные заголовки; сценарий
  page boundary предварительно создаёт 10 задач через список, поэтому он самый
  длительный в наборе.
