# KAN-068 — Отдельный глобальный search-плагин

Дата: 2026-11-25. Реализация: worktree
`.worktrees/kan-068-global-search-plugin`, ветка
`feat/kan-068-global-search-plugin` от `dev`. Push/merge/rebase/amend не

## Результат

- Добавлен публичный SearchProvider Registry в SDK/kernel. Провайдер объявляет
  `id`, `kinds`, `filterFields`, `listFacets()`, `search()` и `reindex()`.
  Регистрация проверяет владельца, непустые типы и уникальность полей;
  деактивация снимает провайдера из реестра без удаления данных.
- `kanbaner.search` не владеет индексом и не читает чужие namespace. Плагин
  агрегирует только активных провайдеров, маршрутизирует `kinds`/`filters` по
  объявленным полям, дедуплицирует по `ResourceRef`, сортирует по score/ref,
  применяет bounded pagination и возвращает `hasMore`.
- Ошибка одного провайдера даёт warning `provider_failed` и сохраняет остальную
  выдачу; чужой `ResourceRef` отбрасывается с warning `foreign_ref`; отказ всех
  провайдеров даёт `DEPENDENCY_UNAVAILABLE`. Неизвестный тип/фильтр и пустой
  текст отклоняются как `VALIDATION_ERROR`. Без активных провайдеров — пустая
  страница.
- Индекс остаётся инфраструктурой активного Storage Provider
  (`core_search_documents`, `core_search_fts`). SQLite WAL и in-memory
  provider синхронизированы по filters/metadata и проходят общую Conformance
  Suite.
- Tasks, notes и fixture регистрируют собственных провайдеров. Tasks объявляет
  `projectId`, `status`, `tags`; notes и fixture не объявляют facet-ов, поэтому
  при project/status/tags-фильтре не вызываются. Reindex выполняется
  идемпотентно при активации домена; отдельной межплагинной reindex-команды нет.
- `kanbaner.search.query` — read-only UI/HTTP/MCP (для будущего
  discovery-driven KAN-069); `kanbaner.search.filters` — UI/HTTP, `mcp:false`.
  Ручной OpenCode allowlist не расширялся.
- UI `/view/search`: динамические типы и facet-ы из
  `kanbaner.search.filters`, text/kind/project/status/tags, loading/error/empty/
  warnings, открытие результата доменным resource-opener-ом кнопкой и
  клавиатурой, mobile layout без горизонтального overflow.
- Search-плагин не зависит от kernel, storage-sqlite, tasks, notes или fixture;
  проверка import boundaries расширена правилами server/UI entrypoint и
  манифеста.

## Review-fix

Повторная доработка после review закрыла lifecycle- и parity-замечания:

- Tasks, notes и fixture выполняют awaited полную переиндексацию **до**
  `registerProvider`. Первая global query сразу после `runtime.start` видит уже
  существующие ресурсы; ошибка `reindex()` прерывает активацию, runtime
  откатывает регистрации и уходит в safe mode. `reindexAllTasks` и
  `reindexAllNotes` логируют `logger.error` и пробрасывают ошибку вместо
  `return 0`.
- `reindexAllNotes()` больше не делает early-return при пустом домене: scoped
  `search.reindex([])` удаляет stale-документы заметок и сохраняет tasks/fixture.
- Валидация неизвестных `kinds`/`filters` перенесена до раннего выхода без
  провайдеров: `VALIDATION_ERROR` одинаков независимо от их наличия, обычный
  текст без провайдеров даёт пустую страницу.
- Формально зафиксирована семантика JSON `metadata`-фильтров: `eq` — точное
  совпадение строкового scalar, `contains` — подстрока строки или точный
  строковый элемент массива; object/number/boolean/null/missing не матчатся.
  SQLite больше не использует `CAST`/`json_extract`-приведение, общий
  conformance-case проверяет все типы на обоих провайдерах.
- UI получил кнопку «Показать ещё» с bounded `offset`, generation guard и
  дедупликацией hits. Новый submit сбрасывает страницу; устаревшие ответы не
  смешиваются с актуальной выдачей.
- Добавлены тесты: register ownership/validation/duplicates, unregister на
  dispose/deactivation/rollback/safe mode, aggregate score/ref, dedupe,
  offset/hasMore, `provider_failed`, `foreign_ref`, all-failed, validation без
  провайдеров; runtime fixtures rollback и deactivation; fixture reindex после
  реально удалённого документа; integration update task/note и delete note;
  HTTP discovery/query с Bearer и 401 без токена; UI load-more/stale/loading/
  errors; E2E поиск заметки.
- E2E открывает заметку через фактический generic resource-opener
  (`?resource=<ref>`): проверяется правильный `ResourceRef` в URL и видимая
  заметка, а не только маршрут. Integration-тест второй активации обновлён под
  awaited reindex: `runtime.start` не завершается, пока gate не отпустит
  переиндексацию.

## Риски

- Merge провайдеров не является межплагинной транзакцией. Порядок определяется
  score/ref, а `hasMore` ограничен страницей; провайдер с очень большим
  `fetchLimit` может вернуть больше кандидатов, но агрегатор всё равно режет
  страницу.
- Metadata фильтров доступна только по объявленным полям. Добавление нового
  поля требует явного изменения `filterFields` и тестов, иначе поле не станет
  каналом чтения чужих данных.
- Reindex каждого домена идемпотентен, но не атомарен между плагинами. Это
  осознанно: команда с частичным успехом не вводится.
- Windows-проверки не выполнялись по явному решению пользователя для текущего
  релиза. Поддержка Windows не отменяется; FTS5 `unicode61` остаётся
  кроссплатформенным контрактом.
- Полный Playwright прогонялся в Chromium; другие браузеры и реальный screen
  reader не проверялись.
