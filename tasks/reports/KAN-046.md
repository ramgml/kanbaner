# KAN-046 — Полноценное дерево заметок с переносом во вложенные

## Итог

Дерево заметок получило три явных сценария drag-and-drop и отдельную корневую
зону:

- drop в среднюю часть строки — страница становится ребёнком цели
  (`note.move` с `parentId = id`, без `position` = добавление в конец ветки);
- drop в верхнюю/нижнюю четверть строки — страница становится sibling до/после
  цели (`parentId = target.parentId`, `position` = индекс среди siblings без
  перемещаемой страницы);
- drop в корневую зону под деревом или на пустое место списка — `parentId = null`.

Публичный контракт `kanbaner.notes.note.move` и доменные инварианты не
менялись: существующей семантики `position` (индекс вставки среди siblings цели,
clamp в домене) достаточно. `expectedVersion` по-прежнему передаётся, `affectedNotes`
из ответа применяются к открытой странице без полной перезагрузки.

## Что изменено

### `packages/plugin-notes/src/ui/note-tree.tsx`

- Добавлены экспортируемые чистые помощники:
  - `noteDropZone(clientY, top, height)` — `before` / `inside` / `after`
    (верхняя и нижняя четверти; без layout безопасно `inside`);
  - `noteMoveRequest(items, draggedId, targetId, zone)` — аргументы `note.move`;
    позиция считается без самой перемещаемой страницы, self/missing → `null`.
- Строка показывает подписанный drop indicator, а не только цвет:
  - `data-note-drop-indicator="before|after"` — линия + текст «Перед»/«После»;
  - `data-note-drop-indicator="inside"` — рамка + бейдж «Внутрь»;
  - корневая зона `data-note-root-drop` получает `data-note-drop-indicator="root"`
    и текст «Отпустите, чтобы сделать корневой».
- Подсказка дублируется в `role="status" aria-live="polite"`
  (`data-note-drop-status`), поэтому смена зоны доступна и без зрения.
- При drop внутрь цель раскрывается до обновления `items`, поэтому перенесённая
  страница сразу видна даже в свёрнутой ветке.
- `dragend`, `dragleave` и drop очищают индикатор; drop на себя не показывает
  зону и не отправляет команду. Перетаскиваемая строка получает
  `data-note-dragging` и `opacity-60`.
- Корневая зона видима всегда: она одновременно служит подсказкой, что перенос
  в корень существует, и целью drop. Компактные отступы KAN-045 сохранены:
  `paddingLeft` по-прежнему `2px` у корня и `+12px` на уровень, overlay KAN-043
  (`data-note-actions`, `pointer-events`, `lg:group-hover/focus-within`) не
  менялся.
- `flat`-режим («Недавние») не получил ни drag-and-drop, ни корневой зоны, ни
  раскрытия; поиск в `notes-view` остаётся плоским списком.

### `packages/plugin-notes/src/ui/notes-view.tsx`

- Перед move выбранной страницы черновик сохраняется; если сохранить не удалось,
  move не отправляется и показывается понятная ошибка.
- Ошибки домена отображаются человекочитаемо:
  `NOTE_TREE_CYCLE` → «Нельзя переместить страницу внутрь её собственной ветки»,
  `NOTE_TREE_TOO_DEEP` → «Превышена максимальная глубина дерева».
- Move не оптимистичен: `refreshNotes` и обновление `details`/`versionRef`
  выполняются только после успешного ответа. При отказе список, selection, путь
  к странице и черновик остаются прежними.
- Сохранены синхронизация версий `result.note + affectedNotes`, пересчёт
  `ancestors` из свежего списка, selection и раскрытие предков.

## Не выполнялось / ограничения

- Реальный mouse-drag HTML5 в Playwright Chromium не воспроизводится (это уже
  зафиксировано в отчёте KAN-045). E2E запускает те же `dragstart`/`dragover`/
  `drop` обработчики синтетическими `DragEvent` с настоящим `DataTransfer`,
  включая live-проверку индикатора. Нативное перетаскивание из ОС не покрыто.
- Keyboard-альтернатива — существующие parent select и кнопки ↑/↓, а не
  отдельный keyboard-режим самого HTML5 DnD. Это соответствует требованию
  задачи «те же операции без drag-and-drop».

## Риски

- Drop на потомка перемещаемой страницы не блокируется на клиенте: домен
  возвращает `NOTE_TREE_CYCLE`, UI показывает ошибку и не меняет дерево. Это
  осознанно: проверка циклов остаётся в домене, без дублирования инварианта в UI.
- Корневая зона занимает около 28 px под деревом; строки и отступы KAN-045 при
  этом не выросли, overlay KAN-043 не менялся.
- При конкурентном изменении соседей между началом drag и `note.move` позиция
  может быть пересчитана доменом; UI после успеха всегда перечитывает список и
  синхронизирует `affectedNotes`, поэтому расхождения не остаётся.
- Добавлять страницу в середину корневого уровня через корневую зону нельзя —
  она добавляет в конец; для точной позиции среди корневых строк есть drop
  before/after на конкретном корневом узле.
