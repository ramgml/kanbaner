## Что сделано

Поиск задач добавлен в оба представления проекта через существующий
`task.list.text`; доменный контракт, `plugin-tasks`, SDK, хранилище и HTTP/MCP
не менялись.

- `q` добавлен в query-state списка и канбана: читается из URL, сериализуется
  и переживает reload и переключение Список ↔ Канбан.
- `resetTaskListFilters` и `resetKanbanFilters` очищают `q`; сброс списка
  дополнительно возвращает `page = 1`.
- В списке изменение `q` сбрасывает страницу (в том числе при вызове
  `updateTaskListQuery` из других мест), а `q.trim()` передаётся как `text`
  только при непустом значении.
- На канбане `text` входит во все запросы колонок, `loadMore`, `filterKey`
  и условия актуальности ответов. Перестановка по-прежнему считает позицию по
  полному scope без `text`, поэтому скрытый поиском сосед не теряется.
- Массовый выбор снимает задачи, переставшие соответствовать `tag` или `q`;
  visibility/mustIncludeIds привязаны к ключу фильтра, включающему поиск.
- Новый переиспользуемый компонент `TaskSearch`: label «Поиск задач»,
  placeholder «Название или описание», Lucide `Search`, доступная кнопка
  «Очистить поиск задач» и лимит 200 символов из контракта.
- Поле хранит локальный draft с debounce 275 мс: `onChange` немедленно
  обновляет видимый ввод, а запрос уходит после паузы или синхронного blur.
  Пока поле в фокусе, router echo не откатывает draft.
- На канбане поле поиска на мобильном делит строку с тегом (`flex-1`), чтобы
  не увеличивать высоту фильтров и не ломать touch-прокрутку доски.

## Исправления первого раунда ревью

- `TaskSearch` был переведён на простой controlled input без debounce; третье
  ревью заменило это на draft+debounce (см. ниже), чтобы router echo не влиял
  на видимый ввод.
- `loadMore` на канбане запрещён до применения первой страницы текущего
  `filterKey`: кнопка скрыта, а обработчик дополнительно проверяет состояние.
- Для защиты от stale cursor в промежутке между сменой query и passive reload
  добавлен `committedFilterKeyRef`, обновляемый в layout effect; ответ
  устаревшего `loadMore` отбрасывается, даже если reload ещё не стартовал.
- Добавлен deferred race test: первая страница нового поиска, затем stale
  `loadMore`, затем свежая вторая страница без пропусков.
- Fake-timer тесты debounce заменены на проверки немедленного `onChange`,
  внешнего reset/open/view-switch и очистки поля.

## Третье ревью: draft вместо history

- Удалены `localSearches`/`lastLocalSearch` из query-state обоих
  представлений; восстановлена исходная синхронизация с router `search`.
- `TaskSearch` снова хранит локальный draft и debounce 275 мс:
  `onChange` немедленно меняет draft и перезапускает timer.
- `onBlur` синхронно фиксирует текущий draft до click-действия, поэтому reset,
  открытие карточки и переключение представления видят уже актуальный `q`.
- Пока поле в фокусе, внешнее `value`/router echo не меняет draft; когда поле
  не в фокусе, внешнее значение синхронизируется.
- Очистка отменяет timer, сразу ставит draft `''` и вызывает `onChange('')`.
- Unmount только отменяет timer, без отложенного `setState`.
- Regression-тесты: быстрый `a → ab` + stale prop `q=a` при фокусе; pending +
  reset; pending + открытие задачи; pending + переход на Канбан; production
  search без `'?'` для списка и канбана. Stale cursor/loadMore fix сохранён.

## Ограничения и риски

- Поиск отправляет запрос после debounce 275 мс или синхронного blur. Клики
  reset/открытия/переключения полагаются на стандартный браузерный порядок
  blur → click; это покрыто unit- и E2E-тестами.
- Пока поле в фокусе, внешнее `value` намеренно не применяется: так router echo
  не откатывает ввод. Внешний reset/open/view-switch сначала снимает фокус и
  фиксирует draft.
- При смене `q` на канбане выбранная карточка снимается (`taskId: null`) так же,
  как при смене тега; в списке выбранная задача сохраняется. Это соответствует
  текущей логике представлений, но поведение различается между видами.
- Новых зависимостей, миграций и изменений публичного контракта нет.
