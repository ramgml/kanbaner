# KAN-020 — Настройки вне рабочей навигации

## Итог

Рабочая навигация shell-а содержит только «Обзор» и доменные пункты плагинов
(в production — «Проекты»). «Плагины» и «Настройки» больше не являются
обычными пунктами sidebar и mobile navigation. Вход в настройки — компактная
иконка шестерёнки с доступным именем «Настройки» внизу desktop sidebar и в
mobile bottom navigation.

Plugin manager перенесён на `/settings/plugins` без изменения компонента,
server actions и lifecycle-поведения. `/plugins` остаётся совместимым адресом
и выполняет серверный redirect на `/settings/plugins`. Safe mode ссылки во
всех трёх местах (notice, sidebar, mobile navigation) ведут на
`/settings/plugins`.

## Поведение

### Sidebar и mobile navigation

- `CORE_NAV_ITEMS` содержит только `/` («Обзор»); `/plugins` и `/settings`
  удалены из массива.
- Доменный пункт «Проекты» по-прежнему приходит из
  `kanbaner.projects.navigation` и отображается и на desktop, и на mobile.
- Внизу desktop sidebar рядом с `Plugin Contract v1` добавлена компактная
  ссылка `settings-link-desktop` (`size-9`, только иконка) с
  `aria-label="Настройки"` и `title="Настройки"`.
- В mobile navigation добавлена компактная ссылка `settings-link-mobile`
  (`w-12`, только иконка) с тем же доступным именем; она не растягивается как
  обычные вкладки и не ломает «Проекты».
- На `/settings` и `/settings/plugins` иконка получает `aria-current="page"`.
- Все ссылки остаются настоящими `next/link` и доступны с клавиатуры через
  Tab/Enter.

### Маршруты

- `/settings/plugins` — новая страница с текущим `PluginManager` и
  `getPluginManagerState()`, `dynamic = "force-dynamic"` сохранён.
- `/plugins` — server component с `redirect("/settings/plugins")` из
  `next/navigation` по текущей документации Next.js. Redirect выполняется до
  рендера plugin manager, поэтому старый адрес не дублирует страницу.
- `/settings` — карточка «Плагины» теперь ведёт на `/settings/plugins`.
- Safe mode notice и обе safe mode ссылки навигации ведут на
  `/settings/plugins`.
- Главная страница не менялась: её карточка `/plugins` автоматически попадает
  на новый адрес через redirect.

### Сохранённое состояние

- `PluginManager` не изменялся: enable/disable, refresh, pending-состояния,
  ошибки и safe mode panel работают как раньше.
- Мобильный bottom sheet проектов, query state, активные представления и
  keyboard-сценарии не затронуты.

## Тесты

- Component-тесты shell проверяют отсутствие «Плагины» в навигации, две
  компактные ссылки настроек, активное состояние на `/settings/plugins`,
  safe mode href и доступные имена.
- `nav-items.test.ts` фиксирует отсутствие `/plugins` и `/settings` в
  `CORE_NAV_ITEMS`.
- E2E `shell.spec.ts`:
  - на 360 px видны мобильная навигация, «Проекты» и компактная иконка
    настроек, горизонтального overflow нет;
  - иконка настроек открывает `/settings`, оттуда — `/settings/plugins` с
    plugin manager;
  - Tab + Enter открывают настройки настоящей клавиатурой;
  - desktop sidebar не содержит «Плагины», а `/plugins` перенаправляет на
    `/settings/plugins`;
  - Space по-прежнему переключает Radix Switch плагина.
- E2E канбана, списка задач и fixture-плагина переведены на
  `/settings/plugins`; сценарий ухода на другой маршрут использует иконку
  настроек вместо удалённого пункта «Плагины».

## Ограничения и риски

- `/plugins` использует временный redirect (307 по умолчанию для
  `redirect()`), а не `permanentRedirect`. Это осознанный выбор: старый адрес
  должен продолжать работать, но не кэшироваться браузером навсегда.
- В `/settings/plugins` заголовок страницы остаётся «Плагины», потому что
  `PluginManager` не менялся по условию задачи.
- Иконка настроек на `/settings/plugins` подсвечивает раздел настроек через
  `aria-current="page"`; это section-level подсветка, а не отдельный пункт
  plugin manager.
- Сценарии Playwright используют общую базу прогона и уникальные названия,
  как и остальные E2E проекта.
