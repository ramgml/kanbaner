# KAN-038 — Блочный BlockNote-редактор заметок

## Что сделано

- Milkdown Kit заменён на `@blocknote/core`, `@blocknote/react` и
  `@blocknote/shadcn` 0.54.0. Удалены Milkdown-зависимость, toolbar, slash-menu,
  `create-note-editor` и declaration shim.
- Стандартный UX BlockNote сохранён: side menu с добавлением блока и drag handle,
  slash-меню с русской локалью, formatting toolbar, link toolbar, таблицы,
  вложенность и DnD. Плагин не переопределяет чужие меню и не добавляет вторую
  component library.
- Canonical остаётся `contentMarkdown`: `note.update`, `expectedVersion`,
  attachment-команды, HTTP API, MCP и схема данных не изменялись. Persisted
  block storage не вводился.
- Автосохранение, конфликт версий, скачивание черновика, readOnly/disabled,
  mobile 360 и keyboard-доступность сохранены.
- `MarkdownNoteEditor` пересоздаёт редактор при смене `noteId`, применяет внешнее
  значение без ложного `onChange`, сравнивает документы с нормализацией переводов
  строк и не публикует изменение при инициализации. Повторный `onChange` с тем же
  Markdown отбрасывается, чтобы смена `editable` не запускала autosave.
- Загрузка изображения через существующий attachment flow: файл уходит в
  `note.attachment.create`, в редакторе показывается data URL, в canonical
  Markdown остаётся `attachment://<id>`. Изображение вставляется в позицию
  курсора; пустой paragraph заменяется image-блоком.
- Подключены `@blocknote/shadcn/style.css` и `@source` для Tailwind, чтобы
  production CSS содержал классы shadcn-компонентов BlockNote.

## Review fixes

- **AST-aware Markdown вместо резки по offsets.** Markdown сначала превращается в
  HTML, image переписываются в inline-контент схемы. Одиночный image верхнего
  уровня остаётся image-блоком; image внутри emphasis/strong, списка, цитаты,
  заголовка и ячейки таблицы сохраняет окружение. Маркеры `**`/`*` больше не
  рвутся.
- **Linked image.** Добавлен inline-узел `linkedImage` для
  `[![alt](url)](href)`. Если внутри ссылки есть ещё текст, ссылка делится на
  текстовые сегменты и `linkedImage`: и ссылка, и картинка сохраняются; attachment
  usage продолжает определяться по inline image.
- **imageReference.** `prepareMarkdownForBlockNote` разрешает reference image
  через `definition` в inline image с фактическим URL и удаляет освободившийся
  definition. Standalone reference становится image-блоком с `props.url`;
  inline reference — inline image; reference внутри ссылки с текстом тоже
  разрешается, поэтому attachment остаётся в usage. Definition, на который
  ссылается обычная ссылка, сохраняется.
- **URL destination.** `sanitizeImageUrl` percent-кодирует пробелы, `()`, `< >`,
  кавычки, backslash и control-символы. Standalone, inline и linkedImage
  сериализуются без обрезки destination; двойной round-trip стабилен.
- **Raw HTML.** `html`-узлы Markdown превращаются в литеральный code span или
  fenced block до BlockNote. `<script>` не исполняется, исходный текст виден в
  редакторе и сохраняется при следующем `onChange`.
- **Ошибки встроенного upload.** `uploadFile` BlockNote получает `blockId`; пока
  блок pending, его пустой/placeholder URL не публикуется в `onChange` и не
  запускает autosave. При ошибке, закрытии или блокировке заметки блок удаляется,
  при успехе возвращается атомарный update `{url, name}`. Скрытый input-flow и
  встроенный paste/drop используют общий обработчик, после `await`
  перепроверяются editor, generation и `locked`.
- **Alt/имя файла.** `sanitizeImageAlt` убирает `]`, `\`, кавычки, скобки,
  control-символы и переводы строк; применяется к загрузкам, импорту Markdown и
  атомарному update встроенного upload. Data URL canonical conversion не ломается.
- Добавлены точные regression-тесты на linked image, image в strong/emphasis,
  ссылку с текстом+image и attachment usage, reference image (тип блока и
  `props.url`), raw HTML и последующий `onChange`, failed built-in upload без
  единого `onChange`/autosave, успешный upload с `]` в alt, блокировку во время
  загрузки, URL с пробелами/скобками и alt с `]`/backslash/newline.

## Ограничения и риски

- BlockNote 0.54 не поддерживает inline image нативно. Adapter показывает такие
  image через custom inline-контент; одиночный image верхнего уровня остаётся
  image-блоком. Структура старых заметок с inline-изображениями сохраняется, но
  image внутри image-блока и inline-image — разные представления при
  редактировании.
- Ссылка с текстом и image внутри делится на текстовые ссылки и `linkedImage`:
  визуально это несколько inline-узлов вместо одной ссылки, но Markdown и
  attachment usage сохраняются.
- Alt/имя файла нормализуется: `]`, `\`, переносы строк и часть служебных
  символов заменяются пробелами. URL с пробелами/скобками percent-кодируется,
  поэтому canonical URL может отличаться от исходного написания.
- Pending-блок встроенного upload не публикуется в `onChange`; при ошибке
  onChange не вызывается вовсе, autosave не запускается. Ограничение: для
  вызовов `uploadFile` без `blockId` pending-блок отследить нельзя, но paste/drop
  и file panel BlockNote передают его.
- Markdown-сериализация BlockNote нормализует синтаксис (маркеры списков,
  выравнивание таблиц, `---` → `***`), поэтому round-trip сверяется по
  фрагментам, структуре блоков и идемпотентности, а не побайтово.
- Реальный drag-and-drop блоков в E2E не автоматизирован: проверены side menu,
  drag handle и keyboard-вложенность. DnD остаётся не единственным способом
  изменения структуры.
- Проверено в Chromium на Linux; Windows, Firefox и WebKit отдельно не
  запускались.
