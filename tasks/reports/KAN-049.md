## Что сделано

Navigation-вклады получили необязательное строковое поле `icon`. SDK не
импортирует React или Lucide: metadata хранит только идентификатор, а shell
сопоставляет его со статическим allowlist компонентов.

- `notes` — `notebook-tabs` (`NotebookTabs`);
- `projects` — `folder-kanban` (`FolderKanban`);
- вклад без `icon` или с неизвестным идентификатором получает прежний `Flag`.

Клиентский registry валидирует непустое значение `icon` и учитывает его в
структурном сравнении `contributionEquals`, поэтому изменение иконки обновляет
вклад и версию реестра.

## Риски и ограничения

- Набор иконок намеренно ограничен статическим allowlist в
  `apps/web/src/components/shell/nav-items.ts`. Новая иконка требует правки shell,
  но не меняет Plugin Contract и не включает динамический импорт.
- `icon` валидируется как непустая строка для любого вида вклада; shell
  использует поле только у `navigation`.
- При первом полном прогоне `pnpm check` один раз упал несвязанный
  `packages/plugin-projects/src/project-settings.test.tsx` (dirty-confirm).
  Изолированный прогон файла и повторный полный `pnpm check` прошли зелёными;
  изменение не затрагивает project settings. Похоже на флейк полного
  параллельного прогона.
