## 4. ESLint: документированное временное исключение

Исходная спецификация требовала ESLint 10.14.x и `eslint-config-next@16.4.5`. Фактическая
установка с `--strict-peer-dependencies` падала: `eslint-plugin-react`, `eslint-plugin-import` и
`eslint-plugin-jsx-a11y`, которые тянет `eslint-config-next`, объявляют peer-диапазон максимум до
ESLint 9.

Пользователь выбрал допустить ESLint 9. Коммит `specs/technology-stack.md` `8eace2b` зафиксировал
`eslint@9.39.x` как единственное временное исключение из запрета deprecated — до появления
совместимого lint-стека. Peer-зависимости при этом остаются строгими:
`peerDependencyRules.allowedVersions` не используется.

В проекте установлен `eslint@9.39.5`. Установка без `allowedVersions` проходит
strict-peer-проверку, а ESLint 9.39.5 успешно запускает flat config с `eslint-config-next` и
`typescript-eslint`.

npm registry помечает все версии `9.39.x` как deprecated (`This version is no longer supported`),
тогда как `10.14.0` не deprecated. Это известное документированное ограничение, явно допущенное
пользователем; `eslint@9.39.5` — единственный deprecated-пакет в lock-файле. Подробности — в
разделе 7.

## 7. Остаточные риски

1. **Deprecated ESLint 9.39.5 — принятое временное исключение.** Все версии 9.39.x помечены npm
   registry как deprecated, поскольку вышел ESLint 10, а `eslint-config-next@16.4.5` пока
   несовместим с ESLint 10. Коммит `specs/technology-stack.md` `8eace2b` явно допускает
   `eslint@9.39.x` как единственное временное исключение из запрета deprecated при сохранении
   строгих peers. Это документированный остаточный риск: исключение нужно снять после появления
   совместимого lint-стека. Отдельного решения в рамках KAN-001 не требуется.
2. **Windows не проверен.** Нативный модуль и кроссплатформенные пути требуют отдельного прогона
   на Windows.
3. **`apps/web/AGENTS.md` генерируется Next.js.** Файл включён в коммит; при обновлении Next.js
   его содержимое может измениться.
4. **`minimumReleaseAgeExclude`** добавлен pnpm 12 для точных версий jsdom и lucide-react,
   которые новее настроенного порога supply-chain policy. Это фиксация конкретных версий, а не
   отключение проверки.
5. **`better-sqlite3` пока только smoke.** Драйвер не обёрнут в асинхронный Storage Provider;
   синхронный API не должен попасть в доменный код до KAN-006/KAN-009.
6. **MCP SDK и Zod установлены заранее** как обязательные peer-зависимости стека, но MCP-адаптер
   не реализован. Это увеличивает дерево зависимостей каркаса.

## 9. Исправление по ревью

Независимое ревью нашло medium-замечание: `prettier.config.mjs` задаёт `endOfLine: "lf"`, но без
`.gitattributes` checkout на Windows с `core.autocrlf=true` мог получить CRLF и сломать
`pnpm format:check` / `pnpm check`.

Добавлен корневой `.gitattributes` с единственным правилом `* text=auto eol=lf`. Оно фиксирует
LF для текстовых файлов независимо от локальных Git-настроек; бинарные файлы определяются
автоматически.

Проверки исправления: `git diff --check`, `pnpm format:check` и полный `pnpm check` прошли
успешно. Исправление оформлено отдельным коммитом
`fix(scaffold): зафиксировать окончания строк LF`.

Минимальное исправление:

- в `.prettierignore` добавлен `.worktrees/` — корневой Prettier не сканирует вложенные worktree;
