## 1. Итог

Создан private pnpm workspace версии `0.1.0-dev.0` с приложением Next.js 16.4.5 на Node.js
runtime и composition root без Storage Provider и доменных плагинов. Пакеты `@kanbaner/kernel` и
`@kanbaner/plugin-sdk` собираются через tsup и импортируются. `better-sqlite3` загружает нативный
модуль и выполняет `SELECT 1` на in-memory базе.

Стек, конфигурации, документы и команды приведены к `specs/technology-stack.md`. Конфликт
ESLint 10 / `eslint-config-next` разрешён изменением спецификации оркестратором: используется
ESLint `9.39.5`, `peerDependencyRules.allowedVersions` удалён.

## 3. Архитектурные решения в рамках задачи

- Корень workspace остаётся тонким: доменной логики, Storage Provider Registry, Store-контрактов,
  миграций, HTTP API и MCP нет.
- `packages/plugin-sdk` содержит только версию Plugin Contract и тип `PluginId`; публичные
  команды, события и ресурсы не добавлялись.
- `packages/kernel` содержит только версии ядра и Plugin Contract. Ядро зависит от
  `@kanbaner/plugin-sdk`, но не от плагинов.
- `apps/web/src/server/composition-root.ts` возвращает `kernel`, `storageProvider: null` и пустой
  список плагинов. Это явная точка расширения для KAN-009.
- Next.js использует App Router, `runtime = "nodejs"` в корневом layout, `serverExternalPackages`
  для `better-sqlite3`, localhost `127.0.0.1:3000`.
- `better-sqlite3` подключён как devDependency приложения и проверяется только smoke-тестом.
  Реальный SQLite Storage Provider, WAL, FTS5 и backup остаются в KAN-009.
- Tailwind 4 подключён через `@tailwindcss/postcss`; shadcn/ui инициализирован через
  `components.json`, `cn()` и CSS-переменные. Компоненты shadcn/ui в каркасе не добавлялись.
- Обязательные peer-зависимости тестового и UI-стека добавлены: Vite 8, jsdom, Testing Library,
  jest-dom, `@vitejs/plugin-react`, Tailwind, `tw-animate-css`, shadcn CLI, MCP SDK и Zod.
- Все скрипты кроссплатформенные: bash, Unix-утилиты и Docker не используются. Проверка
  composition root запускается обычным `node` с нативным type stripping Node.js 24.

## 4. ESLint: разрешённый конфликт

Исходная спецификация требовала ESLint 10.14.x и `eslint-config-next@16.4.5`. Фактическая
установка с `--strict-peer-dependencies` падала: `eslint-plugin-react`, `eslint-plugin-import` и
`eslint-plugin-jsx-a11y`, которые тянет `eslint-config-next`, объявляют peer-диапазон максимум до
ESLint 9.

По решению пользователя/оркестратора спецификация обновлена: ESLint `9.39.x`. В проекте
используется `eslint@9.39.5`; `peerDependencyRules.allowedVersions` и комментарий к нему удалены.
Установка без `allowedVersions` проходит strict-peer-проверку. ESLint 9.39.5 успешно запускает
flat config с `eslint-config-next` и `typescript-eslint`.

Отдельно зафиксирован остаточный конфликт: npm registry помечает все версии `9.39.x` как
deprecated (`This version is no longer supported`), тогда как `10.14.0` не deprecated. Это
следствие обратной совместимости `eslint-config-next`; одновременно выполнить требования
«ESLint 9.39.x» и «ноль deprecated-пакетов» невозможно. Подробности — в разделе 7.

## 6. Невыполненные проверки

Windows недоступен в текущем Linux-окружении, поэтому не выполнены:

- чистая установка зависимостей на Windows;
- загрузка/сборка `better-sqlite3` из prebuilt binary или исходников на Windows;
- production build и запуск приложения на Windows;
- проверка путей `KANBANER_DATA_DIR` с `%APPDATA%`, пробелами и не-ASCII символами на Windows.

Windows-специфичные риски описаны в README: при отсутствии prebuilt-бинарника нужны Python 3 и
Visual Studio Build Tools. Проверки Linux не имитируют Windows.

Не выполнялись как не входящие в объём KAN-001:

- Storage Provider Registry, Store-контракты, миграции;
- SQLite WAL, FTS5, `.backup()` и singleton соединения (KAN-009);
- HTTP API, MCP-адаптер;
- доменные плагины, задачи, заметки, канбан, поиск;
- E2E-тесты Playwright;
- production-проверка реального нативного провайдера (перенесена в KAN-009).

## 7. Остаточные риски

1. **Deprecated ESLint 9.39.5.** Все версии 9.39.x помечены npm registry как deprecated, поскольку
   ESLint 10 уже вышел. `eslint-config-next@16.4.5` пока несовместим с ESLint 10. Это
   неустранимое противоречие текущих требований; нужен либо явный допуск deprecated ESLint 9 в
   спецификации, либо обновление lint-стека после выхода совместимых плагинов.
2. **Windows не проверен.** Нативный модуль и кроссплатформенные пути требуют отдельного прогона
   на Windows.
3. **`apps/web/AGENTS.md` генерируется Next.js.** Файл включён в коммит; при обновлении Next.js
   его содержимое может измениться.
4. **`minimumReleaseAgeExclude`** добавлен pnpm 12 для точных версий jsdom и lucide-react,
   которые новее настроенного порога supply-chain policy. Это фиксация конкретных версий, а не
   отключение проверки.
5. **`better-sqlite3` пока только smoke.** Драйвер не обёрнут в асинхронный Storage Provider;
   синхронный API не должен попасть в доменный код до KAN-006/KAN-009.
6. **MCP SDK и Zod установлены заранее** как обязательные peer-зависимости стека, но MCP-адаптер
   не реализован. Это увеличивает дерево зависимостей каркаса.
