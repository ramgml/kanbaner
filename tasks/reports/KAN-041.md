# KAN-041 — Диагностика пропажи проектов

## Итог диагностики

Проекты не потеряны и код их не скрывает. Запущенный dev server работает с
дефолтным каталогом данных `~/.local/share/kanbaner/data`, который пуст для
namespace `kanbaner.tasks`, а реальные проекты и задачи лежат в неактивной
локальной базе `/work/projects/kanbaner/.data/manual`.

Причина operational: dev server запущен без
`KANBANER_DATA_DIR=/work/projects/kanbaner/.data/manual`. В процессе сервера
переменная `KANBANER_DATA_DIR` отсутствует, поэтому `resolveDataDirectory`
выбирает каталог ОС (`packages/storage-sqlite/src/paths.ts`).

Продуктовый код не изменялся. Regression-тест для неверного operational env не
добавлялся: это не дефект продукта, а неверно заданное окружение запуска.

- `fuser -v` по `.data/manual/kanbaner.sqlite`: файл не открыт.
- `sha256sum` DB и WAL до и после копирования и после harness-прогона: совпадают.
- `stat` timestamps исходной и дефолтной баз.
- Чтение фактических `OperationResult` через UI-транспорт запущенного сервера.
- Focused vitest-прогон временного диагностического теста (удалён после
  прогона) на копии `.data/manual` через application composition:
  1 файл / 1 тест passed.
- `pnpm build:packages` в worktree (нужен для загрузки плагинов из `dist`);
  исходники не менялись.
- `pnpm check` не запускался: продуктовый код не изменялся.

Побочный эффект ранней разведки через UI: открытие `/view/notes` на дефолтной
базе обновило `lastOpenedAt` заметки `note-2fa9ab0a-...` (штатное поведение
приложения). Содержимое заметок и база `.data/manual` не изменялись.

## Рекомендация по перезапуску

1. Остановить текущий dev server (он держит дефолтную базу).
2. Запустить с явным каталогом данных:

   ```bash
   cd /work/projects/kanbaner
   KANBANER_DATA_DIR=/work/projects/kanbaner/.data/manual pnpm dev
   ```

3. Проверить в UI, что workspace показывает 3 проекта, а datalist связей
   заметок предлагает их ResourceRef.
4. Выяснить, почему переменная потерялась при запуске (профиль оболочки,
   ярлык/лаунчер или ручной запуск без env), чтобы не переключать базы снова.
   Дефолтный каталог менять не нужно: он соответствует README и
   `specs/architecture.md`.

## Риски и ограничения

- Диагностика выполнена на копии; в копии WAL мог быть частично checkpoint-нут,
  но набор проектов и задач совпал с ожидаемым и внутренне согласован.
- Если пользователь ожидал данные в дефолтном каталоге, это отдельный вопрос
  миграции/переноса данных и требует явного решения владельца.
