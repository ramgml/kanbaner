# KAN-036 — Markdown в описании карточки и подсказке

## Что сделано

- Добавлен общий `packages/plugin-projects/src/ui/markdown-content.tsx` на
  `react-markdown@10.1.0` и `remark-gfm@4.0.1`.
- Modal и hover/focus tooltip больше не показывают Markdown-маркеры как plain
  text: поддерживаются заголовки, акценты, списки, task list, ссылки, код,
  цитаты, таблицы, зачёркивание и изображения.
- Стили используют текущие light/dark токены; pre и длинная подсказка сохраняют
  прокрутку, изображения ограничены шириной контейнера.
- Raw HTML отключён через `skipHtml`; `dangerouslySetInnerHTML` и `rehype-raw`
  не используются. Применяется стандартный `defaultUrlTransform`: отклонённые
  javascript-ссылки отображаются обычным текстом без пустого перехода.
- Безопасные ссылки получают `target="_blank"` и `rel="noreferrer nofollow"`;
  remote-изображения — `loading="lazy"` и `referrerPolicy="no-referrer"`.
- Textarea продолжает редактировать исходный `descriptionMarkdown`; доменная
  схема, команды и `/view/tasks` не изменены.
- Область описания стала `role="group"` вместо большого button, поэтому
  Markdown-ссылки не вложены в интерактивный button. Click/Enter/touch по ссылке
  не запускает редактор; click по остальной области и Enter/F2 сохраняют прежнее
  поведение.
- `scripts/check-import-boundaries.mjs` явно разрешает две новые UI-зависимости.
- В `specs/technology-stack.md` зафиксирован выбранный Markdown-стек, в
  `specs/product-mvp.md` — поведение чтения описания.

## Тесты

- Новый `markdown-content.test.tsx`: CommonMark, GFM task list/table, code,
  safe/unsafe URL, raw HTML, атрибуты ссылок и изображений.
- Tooltip component test проверяет heading/strong и отсутствие Markdown-маркеров.
- Modal component test проверяет `role="group"`, рендер и незапуск редактора по
  click/keyboard на ссылке; обычный click по-прежнему открывает textarea.
- Production E2E проверяет modal и tooltip, длинную прокрутку, hover/focus,
  DnD, task list, ссылки, отсутствие script/XSS и отсутствие исходных маркеров.
- Старые точные текстовые assertions отделены от проверки исходника: rendered
  DOM проверяется по heading/содержимому, а `textarea.value` подтверждает, что
  исходный Markdown сохранился без изменений.
