# KAN-048 — Исправить CSS resize sidebar

## Итог

Причина Build Error была не в самом Tailwind-классе, а в комментарии hook-а.
`use-note-sidebar-resizer.ts` документировал ширину записью `lg:w-[var(...)]`;
Tailwind v4 сканирует и комментарии, вытаскивал из неё кандидат с литеральным
плейсхолдером `...` и генерировал в `globals.css` невалидное правило
`width: var(...)`. PostCSS падал на парсинге ещё до рендера страницы, поэтому
`/view/notes` отдавал 500 и в dev, и при production build.

Что сделано:

- класс `<aside>` переведён на валидный arbitrary property
  `lg:[width:var(--note-sidebar-width)]` (поведение то же: ширина задаётся CSS-
  переменной только внутри `lg:`);
- из комментария hook-а убрана запись класса, которая попадала в scan Tailwind;
  это единственное изменение в hook-е — resize-логика, константы и
  `asideStyle` не тронуты;
- добавлены два unit-теста: на отсутствие Tailwind-кандидатов с плейсхолдером в
  исходниках плагина и на desktop-класс ширины.

## Что изменено

### `packages/plugin-notes/src/ui/notes-view.tsx`

- `aside`: `lg:w-[var(--note-sidebar-width)]` →
  `lg:[width:var(--note-sidebar-width)]`. Класс остаётся на `lg`-breakpoint,
  поэтому полноэкранный mobile-sidebar (`fixed inset-0`) по-прежнему не
  получает ширину дерева.

### `packages/plugin-notes/src/ui/use-note-sidebar-resizer.ts`

- Только комментарий к `NoteSidebarResizer.asideStyle`: убрана запись
  `lg:w-[var(...)]`, из-за которой Tailwind генерировал `width: var(...)`.
  Код hook-а, константы, pointer/клавиатурное поведение и `localStorage` не
  менялись.

### `packages/plugin-notes/src/ui/notes-view.test.tsx`

- `«не оставляет в исходниках Tailwind-кандидатов с плейсхолдером»` — рекурсивно
  читает `src` плагина и падает, если в `.ts/.tsx/.css` встретится кандидат вида
  `<utility>-[…...…]`. Это ровно тот путь, по которому ломался CSS: Tailwind
  сканирует и комментарии, а не только `className`.
- `«задаёт ширину дерева desktop-классом arbitrary property»` — проверяет, что
  у `<aside>` есть `lg:[width:var(--note-sidebar-width)]` и переменная реально
  применяется.

`globals.css:3123 .lg\:w-\[var\(\.\.\.\)\] { width: var(...); }` → `Parsing CSS
source code failed`.

## Не выполнялось / ограничения

- `pnpm check:imports` в этой задаче отдельно не запускался: границы импортов не
  менялись (правки только в UI-плагине и его тестах), `check` границы не
  покрывает — если нужна формальная фиксация, запускать отдельно.
- Guard-тест ловит только плейсхолдер `...` в произвольных значениях. Другие
  гипотетические «мусорные» кандидаты из комментариев он не ищет.
- E2E проверяет Chromium; Firefox/WebKit в набор не входят.

## Риски

- Tailwind сканирует все файлы из `@source`, включая тесты и комментарии:
  любая будущая запись класса с плейсхолдером внутри `[...]` снова сломает
  `globals.css`. Guard-тест покрывает только этот конкретный шаблон.
- Класс ширины задан через arbitrary property `[width:…]`, а не через
  `w-…`: это осознанно, но при добавлении `w-*` рядом порядок слоёв Tailwind
  может перебить ширину — сейчас такого класса у `<aside>` нет.
