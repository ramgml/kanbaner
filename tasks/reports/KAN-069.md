## Что сделано

Создан автономный private-пакет `@kanbaner/mcp` версии `0.1.0-dev.0` с
executable `kanbaner-mcp-universal` и server name `kanbaner-universal`. Пакет
не импортирует kernel, storage, доменные плагины или `apps/**` и не открывает
базу данных.

### Конфигурация и запуск

- `KANBANER_API_URL` — только абсолютный HTTP(S) URL без credentials, query и
  hash; завершающий `/` нормализуется.
- `KANBANER_API_TOKEN` — обязателен; поддержан безопасный срез префикса
  `KANBANER_API_TOKEN=`. Токен не попадает в сообщения, ошибки и stdout.
- `KANBANER_MCP_TIMEOUT_MS` — целое от 1 до 120000, по умолчанию 15000.
- `KANBANER_MCP_ALLOW_DESTRUCTIVE` — строго `true`/`false`, по умолчанию
  `false`.
- `src/cli.ts` проверяет конфигурацию до подключения транспорта: при ошибке
  exit code 2 и безопасное сообщение в stderr. SIGINT/SIGTERM закрывают server
  и завершают процесс; stdout отдан только stdio JSON-RPC.

### Discovery и каталог tools

- `GET /api/v1/discovery` перечитывается при каждом `tools/list` и
  `tools/call`; статического кэша нет.
- Ожидается конверт `{ok: true, data: {apiVersion, contractVersion,
operations}}` с `apiVersion = 1` и `contractVersion = 1`.
- Если операции есть, но ни у одной нет `exposure`, возвращается
  `DISCOVERY_INCOMPATIBLE`; пустой список операций допустим. Отдельные
  некорректные descriptors пропускаются.
- Публикуются только `exposure.http === true && exposure.mcp === true`.
- Имя tool: lowercase, недопустимые символы → `_`, обрезка краевых `_`,
  максимум 128 символов. Пустые/длинные имена и обе стороны коллизии
  исключаются с диагностикой в stderr.
- Каталог сортируется по имени. Annotations: query — read-only/idempotent,
  mutation — write, destructive — `destructiveHint: true`.
- `expectedVersion` не подставляется: marker и описание появляются только если
  поле есть в `required` входной схемы.
- Destructive операции не экспортируются без явного
  `KANBANER_MCP_ALLOW_DESTRUCTIVE=true`; при включении имеют
  `DESTRUCTIVE.`-prefix и destructive annotation.

### Вызов операций

- Query вызывается через `POST /api/v1/queries/{id}`, mutation — через
  `POST /api/v1/commands/{id}`.
- Все запросы используют Bearer token, `x-kanbaner-client: mcp`,
  `redirect: "error"`, bounded timeout и caller abort.
- Вход валидируется локально по discovery JSON Schema до HTTP-запроса;
  невалидный вход не вызывает HTTP.
- Object output schema валидируется по `outputSchema`. Non-object output
  schema не публикуется как MCP `outputSchema` и адаптером не валидируется:
  discovery отбрасывает её, а массив/примитив остаётся только text content.
- `structuredContent` возвращается только для object output schema; массивы и
  примитивы остаются обычным text content.
- `Idempotency-Key` создаётся только для mutation с `idempotency: "supported"`
  и учитывает operation, input, requestId, sessionId, instanceId и processId.
  Query и mutation с `none` ключ не получают.
- Для mutation с `idempotency: "none"` все неопределённые post-dispatch
  транспортные сбои — rejected fetch, ошибка чтения тела, non-JSON fallback
  (включая 504) и таймаут — возвращаются с `retryable: false`. Query и
  supported mutation сохраняют retryable-политику; валидный серверный
  `OperationEnvelope` остаётся authoritative и не переписывается.
- Готовый protocol descriptor каждого tool дополнительно проверяется через
  `ToolSchema.safeParse` установленной MCP SDK. Не прошедший проверку tool
  отбрасывается целиком, остальной `tools/list` продолжает работать.

### Ошибки и redaction

- Стабильные коды: коды `@kanbaner/plugin-sdk` плюс `DISCOVERY_INCOMPATIBLE`
  и `UNKNOWN_TOOL`; для HTTP-статусов — `PERMISSION_DENIED`, `NOT_FOUND`,
  `RATE_LIMITED`, `DEPENDENCY_UNAVAILABLE`, `TIMEOUT`, `INTERNAL_ERROR`.
- Protocol-level `McpError` содержит `{code, retryable}` и не раскрывает тело
  ответа или upstream headers.
- Details передаются только для `VALIDATION_ERROR`, `VERSION_CONFLICT` и
  `IDEMPOTENCY_CONFLICT`; остальные details отбрасываются.
- Redaction сначала заменяет токен во всём тексте и только затем обрезает
  сообщение до 500 символов, поэтому токен на границе или длиннее лимита не
  просачивается.
- Разрешённые details рекурсивно санитизируются: строковые ключи и значения,
  ограничение глубины/числа узлов/длины массивов, JSON-safe значения. Опасные
  ключи (`__proto__`, `constructor`, `prototype`) и Ajv `params` не
  передаются; локальная validation не раскрывает входные значения.
- `tools/list` принимает request `extra` и передаёт `extra.signal` в discovery
  fetch, поэтому abort клиента доходит до HTTP.

## Review-fix после этапа A

Повторное ревью выявило один high, три medium и три low-замечания; все
исправлены без расширения публичного контракта и без новых зависимостей.

### High: post-dispatch сбои mutation none

- `JsonRequestOptions.retryableOnTransportFailure` заменяет прежний
  timeout-only флаг.
- Для mutation с `idempotency: "none"` non-retryable теперь не только
  локальный timeout, но и rejected fetch, ошибка чтения тела, non-JSON
  fallback любого HTTP-статуса (включая 504) и fallback без валидного
  `OperationEnvelope`.
- Query и supported mutation сохраняют прежнюю политику, а валидный серверный
  `OperationEnvelope` не переписывается.
- Regressions: rejected fetch, text error, non-JSON 504; controls для query,
  supported mutation и серверного envelope.

### Medium: redaction, abort list и ToolSchema

- Секрет вырезается из полного message до `slice(0, 500)`; тесты покрывают
  токен на границе и токен длиннее 500.
- Details проходят bounded JSON-safe traversal: редактируются ключи и значения,
  ограничены глубина/узлы/массивы, отбрасываются не-JSON значения,
  `__proto__`/`constructor`/`prototype` и `params`. Локальная validation больше
  не отдаёт Ajv `params`.
- `tools/list` получает `extra` и передаёт `extra.signal` в discovery fetch;
  InMemory Client abort проверен до фактического abort signal в fetch.
- Перед публикацией descriptor проверяется через `ToolSchema.safeParse`;
  boolean subschema в `properties` отбрасывается, остальной список остаётся
  доступным.

### Low: token prefix, moveMany и output schemas

- `normalizeApiToken` считает missing не только пустую строку, но и
  `KANBANER_API_TOKEN=` / `KANBANER_API_TOKEN=   ` после среза префикса;
  `loadConfig` fail-fast.
- `moveMany` тест исправлен на фактическое имя
  `kanbaner_tasks_task_movemany`, fixture получил `mcp:false`, добавлен
  camelCase naming test — без ложного negative.
- Отчёт уточняет output schemas: object валидируется и публикуется,
  non-object не публикуется как MCP `outputSchema` и не валидируется
  адаптером.
