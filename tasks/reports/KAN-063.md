# KAN-063 — Копирование кода и черновики по OpenCode-сессиям

Дата: 2026-11-23. Реализация: worktree
`.worktrees/kan-063-code-copy-session-drafts`, ветка
`feat/kan-063-code-copy-session-drafts` от `dev`. Push/merge/rebase/amend не
выполнялись.

## Результат

- `MarkdownContent` получил additive optional `codeBlockAction`. Без prop
  разметка и поведение не меняются; с prop action получает точный plain text
  fenced/indented code block без одного renderer-added trailing newline. Inline
  code и пустой fence action не получают, `skipHtml` и sanitization URL
  сохранены.
- Текст блока извлекается из HAST рекурсивно только по text-узлам. Нет
  `dangerouslySetInnerHTML`, `innerHTML`, `MutationObserver` и второго
  renderer. Action монтируется overlay-контейнером рядом с `pre`; размеры,
  `overflow-x-auto` и позиция чтения не меняются.
- `CodeBlockCopyAction` — native `<button type="button">` с `aria-label`/`title`
  `Копировать код`, `Код скопирован`, `Не удалось скопировать код`, иконками
  Copy/Check/X, `focus-visible` и мобильной целью 36 px. Сброс через 2 секунды,
  таймер очищается при unmount и StrictMode-remount. Второй live-region не
  добавляется, `followNow` не вызывается.
- Копирование сначала использует `navigator.clipboard.writeText`; при
  отсутствии API, отказе или rejected Promise — legacy
  `document.execCommand("copy")` через временную readonly offscreen textarea.
  `activeElement` и Selection ranges восстанавливаются в `finally`, пустая
  строка не копируется, ошибка не покидает функцию rejected Promise-ом.
- Черновики composer хранятся по session ID в одном ключе
  `kanbaner.opencode.drafts.v1` формата
  `{ v: 1, drafts: { [sessionID]: { text, updatedAt } } }`.
- Лимиты: 16 384 символа на запись, 20 записей и 65 536 символов суммарно. LRU
  удаляет самые старые по `updatedAt` записи (tie-break по session ID).
  Сверхлимитный ввод остаётся в памяти composer, но не сохраняется;
  `maxLength` в textarea не добавляется, старая запись этой сессии
  детерминированно удаляется.
- Пустой текст удаляет запись, последняя запись удаляет ключ. Невалидный
  JSON/version/shape, `NaN`/отрицательное время и oversize entry игнорируются
  по отдельности. Все get/set/remove обёрнуты в try/catch.
- В storage попадает только текст composer. Вложения, base64, preview URL,
  сообщения, история, turn/model, attached refs, ошибки и токены не
  сохраняются.
- Черновик изолирован по сессии, переживает закрытие панели и reload, новая
  сессия не получает чужой текст. `send()` очищает черновик только своей сессии
  и только после существующей точки optimistic append. Retry не очищает
  изменённый пользователем composer; unconfirmed/error до optimistic append
  черновик сохраняет. `clearComposer` входит в снимок `PromptAttempt`.
- `kanbaner.opencode.sessionId` использует safe get/set/remove wrappers.
  Заблокированный или переполненный `localStorage` не ломает initialize панели
  и composer, а ошибки storage не маскируются под сбой OpenCode Service.
- Stable turn/admission/canonical semantics, compact tools, scroll/unread/focus,
  redaction и StrictMode не изменены. Все 17 прежних scroll E2E-сценариев
  остались зелёными.

## Ограничения

- Полноценный список сессий появится в KAN-064; переключение проверено через
  существующее восстановление последней сессии и ручную смену ID в E2E.
- Черновик не синхронизируется между вкладками и не сохраняет позицию курсора
  или выбранные вложения.
- LRU при равном `updatedAt` использует лексикографический session ID; это
  детерминированно, но не отражает реальный порядок редактирования при
  одинаковой millisecond-метке.
- Проверки выполнены на Chromium; другие браузеры и Windows в этом срезе не
  тестировались. Legacy clipboard fallback в E2E проверен через отказ
  `execCommand`, реальный системный clipboard другого браузера не тестировался.
- Worker не выполнял push/merge/rebase; интеграцию выполняет оркестратор.
