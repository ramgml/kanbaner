# KAN-060 — Статусы prompt и ручная проверка результата

Дата: 2026-11-23. Реализация: worktree `.worktrees/kan-060-prompt-status`,
ветка `feat/kan-060-prompt-status` от `dev`. Push/merge/rebase не выполнялись.

## Результат

- Stream-контракт `OpenCodeStreamEvent` получил стадию `finalizing` и
  необязательный `reason: "unconfirmed"` у terminal error.
- Gateway выпускает внутреннее `session.execution.finalizing` ровно один раз
  перед canonical lookup — и для terminal-события, и для transport error.
  Событие не является terminal и не подтверждает done.
- Canonical outcome по-прежнему определяется точным user-turn
  (`type=user && id === turnID`) и завершённым assistant, а не типом
  upstream-события. Каждый prompt получает client-generated stable turn ID
  (`^msg_[A-Za-z0-9_-]{8,64}$`), который передаётся в `session.prompt({ id })`;
  при подмене ID Service выпускается `kanbaner.turn.admitted` и сохраняется
  alias client→admitted. Сбой lookup повторяется в пределах общего deadline
  (`CANONICAL_ATTEMPTS = 3`, `CANONICAL_DELAY_MS = 50`,
  `CANONICAL_DEADLINE_MS = 600`); после deadline выдаётся
  `error` с `reason: "unconfirmed"`.
- HTTP NDJSON transport пробрасывает `finalizing` без terminal-семантики,
  не добавляет fallback terminal после `finalizing`, не дублирует terminal и
  подавляет generic error после уже полученного terminal. Неопределённые сбои
  дают unconfirmed без upstream-текста.
- UI ведёт generation-guarded статус turn:
  `connecting → running → finalizing → done/cancelled/error`. Terminal-статус
  (`done`, `cancelled`, `error`) сохраняется после завершения запроса и не
  исчезает в `finally`.
- Ошибки разделены: `panelError` (catalog/status панели), `selectionError`
  (форма/вложения, `role="alert"` в composer) и turn-scoped статус
  (`data-testid="opencode-turn-status"`, `role="status"`, ниже сообщений перед
  composer).
- Для unconfirmed UI показывает «Результат не подтверждён», сохраняет уже
  streamed-сообщения и кнопку «Проверить статус». Автоматический canonical
  refresh и повтор prompt в этом состоянии не выполняются.
- «Проверить статус» использует
  `GET /api/opencode/session/{sessionID}?turnID={turnID}`, где `turnID` —
  client-generated stable ID исходного prompt (не ordinal), не создаёт prompt
  и не теряет сообщения. Сервер возвращает `{ session, outcome }`, где
  `outcome` — `done`, `error`, `cancelled`, `pending` или `missing`.
  UI применяет canonical history только при `done`; возможные исходы: pending
  («Результат пока не подтверждён. Проверьте ещё раз позже.»), done, canonical
  error/cancelled (streamed-сообщения сохраняются), либо публичная ошибка
  проверки («Не удалось проверить статус: …»). Устаревший ответ после смены
  сессии отбрасывается по generation/sessionID.
- Автоматический повтор доступен только для точно не принятого retryable
  запроса (408/429/≥500): повтор отправляет снимок исходных текста и файлов.
  4xx и любые post-admission ошибки/неопределённость не повторяются; для них
  доступна только ручная проверка статуса.
- Сохранены strict SemVer major 2.x, exact user-turn, redaction, bounded
  lookup, stale cancelled filtering, keyboard/mobile accessibility, вложения,
  tool mapping, Markdown, canonical verification и StrictMode-поведение.
  Новых зависимостей и изменений lock-файла нет.

## Review-fix

Независимое ревью выявило гонки подтверждения prompt; все findings закрыты
отдельным коммитом `fix(opencode): устранить гонки подтверждения prompt`.

- **BLOCKER — retry после возможного admission.** UI больше не полагается на
  тип исключения `fetch` и не повторяет prompt, если отправка могла дойти до
  Service. Rejected `fetch`, `body === null`, неизвестный исход и любой обрыв
  после старта запроса дают `unconfirmed`, `retryable:false` и только
  «Проверить статус». HTTP transport также не выставляет retryable после
  возможного admission. Regression: stream отклонён после первого delta —
  один POST, текст сохранён, кнопки повтора нет.
- **HIGH 1 — ручная проверка по точному turn.** `getTurnStatus(sessionID,
turnID)` вычисляет canonical outcome на сервере для переданного stable ID;
  pending/missing не считаются done. UI запрашивает
  `GET /api/opencode/session/{sessionID}?turnID=` и не интерпретирует свой
  текст/ordinal. Regression: done/error для точного ID, missing для
  отсутствующего, второй prompt ищется по своему ID.
- **HIGH 2 — потеря streamed-текста.** При `error`, `cancelled` и pending
  streamed-сообщения сохраняются; canonical history заменяет их только при
  `done`. Regression: delta → finalizing → manual error/cancelled сохраняет
  «Черновик».
- **MEDIUM 1 — классификация HTTP-ошибок.** `OpenCodeGatewayError` до первого
  streamed-события даёт redacted terminal error с `nonAdmission:true`;
  `retryable` только для `DEPENDENCY_UNAVAILABLE`/408/429/5xx. Неизвестная
  ошибка после admission — unconfirmed без upstream-текста. Terminal после
  `finalizing` не дублируется.
- **MEDIUM 2 — stable turn ID.** Вместо ordinal введён client-generated
  `turnID` (`^msg_[A-Za-z0-9_-]{8,64}$`), пятый optional аргумент `prompt`,
  `kind:"admitted"` и alias-map. Prompt передаёт `SessionPromptInput.id`.
  Regression: второй prompt проверяется по своему ID, подмена ID связывается
  явным событием.
- **LOW — покрытие.** Добавлены задержанные проверки всех четырёх фаз,
  success E2E с `finalizing`, E2E manual done/error/pending, unsafe rejected
  fetch, stable ID второго prompt, empty/tool-only/cancelled и сохранение
  streamed-текста.

Обновлены `packages/opencode/README.md`, `specs/product-mvp.md` §6.7,
`specs/architecture.md`, `specs/technology-stack.md` и этот отчёт.

## Второй review-fix

Повторное ревью подтвердило предыдущие исправления и выявило ещё один blocker
и medium; они закрыты коммитом `fix(opencode): безопасно обработать admission prompt`.

- **BLOCKER — rejected `client.session.prompt()`.** Раньше rejected Promise
  попадал в ветку pre-admission и мог стать `nonAdmission:true/retryable:true`,
  хотя обрыв соединения после admission не доказывает, что Service не принял
  запрос. Теперь `promptAttempted` ставится непосредственно перед вызовом;
  ошибка после начала вызова запускает существующий bounded canonical lookup
  по stable client turn ID и даёт terminal только при exact canonical outcome
  (`done`/`error`/`cancelled`), иначе `unconfirmed` с `retryable:false`.
  Pre-admission `OpenCodeGatewayError` наружу больше не выбрасывается;
  автоматический retry/interrupt после начала вызова не выполняется, кроме
  существующей явной abort-семантики. HTTP помечает non-admission только если
  gateway не выдал ни одного события.
- **MEDIUM — admitted ID вне client pattern.** `turnID` prompt body остаётся
  strict client-generated (`^msg_...`). Для status query и admitted event
  добавлен отдельный bounded validator
  `isOpenCodeAdmittedTurnID` (charset `[A-Za-z0-9._:-]`, длина 1–128) без
  требования `msg_`. `getTurnStatus` принимает исходный client ID через
  alias-map и прямой admitted `SessionMessageID`; прямой ID работает после
  eviction alias-map и restart. Integration regression использует
  `inbox-admitted` в gateway → HTTP → UI.

Regression-тесты: rejected prompt с canonical done/error/unconfirmed и без
`nonAdmission`/`retryable` в NDJSON; один POST и отсутствие retry в UI;
принятие `inbox-admitted` в status query и отказ для prompt body; ручная
проверка UI по admitted ID.

## Ограничения

- Проверка статуса опирается на тот же публичный `GET` session; отдельного
  серверного статуса prompt нет.
- После unconfirmed пользователь сам решает, когда повторить проверку; окно
  автоматического lookup ограничено deadline и не продлевается.
- Windows и браузеры кроме Chromium в этом срезе не проверялись.
- Push не выполнялся; `dev` и `main` не изменялись.
