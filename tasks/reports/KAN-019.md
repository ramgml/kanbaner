# KAN-019 — Рабочее пространство проектов

## Итог

`kanbaner.kanban` и `kanbaner.task-list` заменены одним UI-плагином
`kanbaner.projects` (`1.0.0`, контракт `kanbaner.projects.ui.v1`). Проекты
переключаются в sidebar и мобильном bottom sheet, доска всегда показывает один
проект, список и канбан переключаются в заголовке проекта, а карточка
создаётся вводом только названия. Домен `kanbaner.tasks` и публичные
commands/queries не изменялись.

## Замена старых Plugin ID

- Удалены из production composition:
  - `kanbaner.kanban`;
  - `kanbaner.task-list`.
- Вместо них активен `kanbaner.projects` с UI-вкладами:
  - `kanbaner.projects.view.kanban`;
  - `kanbaner.projects.view.tasks`;
  - `kanbaner.projects.view.overview`;
  - `kanbaner.projects.navigation`;
  - `kanbaner.projects.sidebar`;
  - `kanbaner.projects.details`;
  - `kanbaner.projects.details-mobile`;
  - `kanbaner.projects.kanban-overlay`;
  - `kanbaner.projects.mobile-sheet`.
- Старые Plugin ID, contribution ID, command ID и event type не
  переиспользуются. Команды и запросы остались в namespace
  `kanbaner.tasks.*`.
- В plugin manager теперь отображается `Kanbaner Projects`. Его отключение
  убирает оба маршрута `/view/kanban` и `/view/tasks`, не удаляя данные задач;
  после включения задачи снова доступны. Composition-тест проверяет 9 вкладов
  (main = 3, sidebar = 2, details = 1, overlays = 3).
- Удалённые E2E selectors соответствуют сознательно удалённому поведению:
  - `kanban-mode-projects` / `kanban-mode-board`, `kanban-projects-*`,
    `kanban-project-badge-*`, `kanban-filter-chip-project` — агрегированная
    доска всех проектов и выбор проекта внутри доски заменены обзором
    `/view/projects` и sidebar;
  - `kanban-create-task-*`, `kanban-create-project`,
    `kanban-quick-add-input-*`, `kanban-quick-details-*`, `task-form-create` —
    полная форма создания на доске заменена коротким composer-ом и формой
    редактирования уже созданной карточки;
  - `kanban-quick-add-*` переупорядочены в
    `kanban-quick-add-<status>-input|form|submit|error`.

## Поведение

### Sidebar и переключение

- В shell один пункт «Проекты» (`kanbaner.projects.navigation`,
  `app.sidebar`) ведёт на `/view/projects?entry=1`; `isActivePath` сравнивает
  только pathname, поэтому query входа не мешает подсветке.
- Обзор по `entry=1` восстанавливает последнее представление
  (`readLastProjectView`) и проект (`readLastProjectId`) либо снимает служебный
  параметр, если сохранённого вида нет. Прямой `/view/projects` остаётся
  обзором.
- Секция «Проекты» показывается только на маршрутах проектов.
- Активный проект помечен `aria-current="page"`.
- Выбор меняет `?project=` без промежуточного экрана и запоминается в
  `localStorage`.
- Поиск включается при большом числе проектов; список прокручивается внутри
  sidebar.
- `project.list` догружается по `nextOffset` страницами по 200 с дедупом по id
  и guard от зацикливания: созданный 201-й проект виден в sidebar и
  открывается, а не считается удалённым.
- На мобильном `projects-mobile-trigger` открывает bottom sheet с тем же
  списком, поиском и созданием.

### Одна доска одного проекта

- `/view/kanban` без `?project=` выбирает последний/единственный проект.
- Если контекст неоднозначен, показывается `kanban-project-picker`, а не
  агрегированная доска.
- Сводка, заголовок и счётчики относятся только к выбранному проекту.

### Список / Канбан

- `project-view-list` и `project-view-kanban` — настоящие `<a href>` (не Next
  Link), построенные общим `ui/view-toggle.tsx` из актуального query state.
  Оба элемента несут `aria-pressed="true|false"` в обоих состояниях и
  `aria-current="page"` у активного вида. Файл содержит осознанный file-level
  `eslint-disable jsx-a11y/role-supports-aria-props` с пояснением.
- Переключатель сохраняет `project`, `tag` и `task`; выбранная карточка
  переносится между панелью деталей списка и overlay-модалом доски. Смена
  проекта снимает `task` прежнего проекта, но сохраняет тег.
- Тот же переключатель рендерится внутри нативного Trello-модала и мобильного
  `dialog` деталей: реальный `<a>` остаётся кликабельным и доступен с
  клавиатуры (focus + Enter), несмотря на inert-фон модала.
- Task-list пишет query через router-aware `registerTaskListSearchWriter` и
  `router.replace`, поэтому заголовок проекта и переключатель получают
  актуальный `workspaceSearch`, а не устаревшее значение пропа.
- Уход на другой маршрут (например, «Плагины») закрывает overlay.

### Создание только по названию

- Общая кнопка и кнопка колонки открывают `TitleComposer` с одним полем.
- Проект определяется доской, статус — колонкой, позиция — доменным append.
- Double-submit guard, сохранение ввода при ошибке, Escape и возврат фокуса
  сохранены.
- Черновик названия хранится в `KanbanView` и переживает размонтирование
  composer-а при смене layout mobile ↔ desktop; после открытия новой сессии
  поле очищается.
- Composer не обрезает ввод по `maxLength`: превышение лимита возвращает
  доменную ошибку валидации, а введённый текст остаётся в поле.
- Полная `TaskForm` используется только для редактирования открытой карточки;
  родитель задаётся публичной формой подзадачи в Trello-модале, потому что
  `task.update` не меняет `parentTaskId`.
- Кнопка «Новый проект» заголовка списка публикует общий
  `requestProjectCreate()`: desktop sidebar и mobile bottom sheet сами
  подписываются на запрос (с gating по `useMediaQuery`) и открывают свою форму.
  Клика по скрытой desktop-кнопке из DOM больше нет; E2E-helper
  `openProjectCreator` использует одну видимую кнопку на обоих breakpoint-ах.

### Исправленные гонки

- Эффект scroll affordance в `kanban-view` не перезапускался, когда доска
  впервые появлялась после асинхронной загрузки проектов. Зависимости эффекта
  дополнены `effectiveProjectId` и `projectsLoading`.
- При автовыборе проекта из `/view/kanban` без `?project=` выбранная задача из
  `?task=` больше не сбрасывается.
- После сохранения conflict-сообщение в списке использует стабильный
  `VERSION_CONFLICT_MESSAGE`, а не текст ошибки, который очищался повторным
  чтением задачи.

### Исправления по ревью

1. **Вход в workspace из shell.** Добавлен
   `kanbaner.projects.navigation` с `route: "/view/projects?entry=1"`;
   `ProjectsOverview` резолвит сохранённый вид/проект и делает
   `window.location.replace`, иначе снимает `entry`. `isActivePath` игнорирует
   query/hash. `ui/registry.ts` теперь сохраняет оригинальный
   `metadata.route` вклада, а нормализованный путь использует только как ключ
   `routes` и для проверки дубликатов, поэтому query навигации не теряется.
2. **Toggle search.** `query-state.ts` получил router-aware writer;
   `TaskListView` регистрирует `replaceSearch`, `useTaskListQuery(search)`
   синхронизируется с router, `ProjectHeader` получает актуальный
   `workspaceSearch`.
3. **Toggle внутри modal.** Общий `ui/view-toggle.tsx` на настоящих `<a>`
   рендерится в заголовке, внутри `TaskModal` (prop `viewSwitch` из
   `TaskOverlay`) и в мобильном `TaskDetailsPanel`. E2E используют обычный
   click и Enter без `evaluate`/обхода inert.
4. **Mobile create-project-button.** Общий `requestProjectCreate()` вместо
   DOM-клика по скрытой desktop-кнопке; форма открывается видимым
   контейнером на текущем breakpoint-е.
5. **>200 projects.** `useProjectsData` догружает `project.list` по
   `nextOffset` (страницы по 200, дедуп по id, guard 100 страниц). Component-
   тест создаёт 201-й проект и проверяет появление, открытие и offset=200.
6. **aria-pressed.** Реализованы оба состояния (`true`/`false`) на `<a>`;
   component- и E2E-тесты проверяют оба значения.

### Повторное ревью

1. **HIGH: draft guard.** `TaskModal` получает `draftDirty`, и переключатель
   скрыт не только при `editing`/`closeConfirm`, но и при любом несохранённом
   быстром черновике: статус, срок, теги или открытая подзадача с названием.
   Component-тест последовательно проверяет каждое поле (toggle исчезает,
   значение остаётся, после отмены черновика возвращается) и полное
   редактирование без регрессии. E2E повторяет сценарий в реальном Chromium и
   дополнительно проверяет, что Escape показывает confirm и сохраняет ввод.
2. **MEDIUM: повторный вход.** `entryHandledRef` сбрасывается, когда
   `entryRequested` становится `false`. Component-тест прогоняет
   `entry → без entry → entry` без remount; E2E дважды кликает «Проекты» на
   `/view/projects` и проверяет, что служебный `entry=1` снимается оба раза.
3. **LOW: localStorage.** `readLastProjectView` обёрнут в `try/catch` и
   возвращает `null` при `SecurityError`, запрете storage или неизвестном
   значении. Новый `ui/workspace.test.ts` проверяет валидное значение,
   мусор и бросающий `getItem`.

    тест пагинации сравнивает порядок с обратным порядком создания; после
    перезагрузки и «В конец» проверяется тот же полный набор без дублей;
  - статус в helper-ах задаётся move-контролом после создания, а не полем
    формы редактирования;
  - после reload выбранная задача восстанавливается из `?task=`, поэтому
    сценарии модала проверяют уже открытый overlay, а не повторный клик по
    карточке за ним;
  - мобильный клавиатурный сценарий снимает фокус кликом по заголовку
    выбранного проекта (`project-board-title`), а не по исчезнувшему
    заголовку «Задачи»;
  - агрегат обзора и суммы карточек используют разные префиксы
    `data-testid`, чтобы не удваивать итог.
- E2E используют общую базу прогона; изоляция обеспечивается уникальными
  названиями и фильтром проекта. Первый сценарий пустого состояния
  выполняется первым при `workers: 1`.

## Ограничения и риски

- Агрегированная доска всех проектов удалена сознательно; её роль выполняет
  обзор `/view/projects`, где есть сводки и переходы, но нет статусной доски.
- Создание карточки больше не принимает описание, теги, срок и родителя за один
  шаг. Эти поля задаются редактированием; родитель — через форму подзадачи.
- Переключение представления сохраняет выбранную задачу, поэтому overlay не
  закрывается при смене списка/канбана — это осознанное изменение прежнего
  поведения.
- `Переместить в` в деталях ставит задачу в начало целевой колонки. Это
  существующее доменное поведение; E2E фиксируют его явно.
- Сценарий пустого состояния E2E по-прежнему выполняется первым при
  `workers: 1`, чтобы база прогона была пустой.
- E2E используют общую базу; изоляция сценариев обеспечивается уникальными
  названиями проектов и фильтром проекта.
