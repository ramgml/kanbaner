## Осознанное ограничение: родитель только при создании

Публичная команда `task.update` не принимает `parentTaskId`, поэтому:

- родитель выбирается только в форме создания задачи;
- в режиме редактирования родитель показан **только для чтения**
  (`lockParent`), выбор отсутствует;
- контракт `kanbaner.tasks` не расширялся, смена родителя не эмулируется
  отдельными командами.

Ограничение зафиксировано в `packages/plugin-task-list/README.md` и покрыто
E2E-проверкой: `select[name="parentTaskId"]` в edit отсутствует, отображается
«Без родителя (корневая)».

## Исправление VERSION_CONFLICT между экземплярами SDK

Симптом: конфликт версий приходил в UI как `INTERNAL_ERROR`
(«Внутренняя ошибка операции»).

Фактическая причина (подтверждена временными серверными логами):

- `plugin-tasks` корректно создавал `TasksVersionConflictError` и маппил его в
  `VERSION_CONFLICT`;
- ядро получало `PluginOperationError`, но `instanceof` давал `false`;
- серверный плагин загружается динамическим `import()` из собственного
  `dist`, поэтому получает второй экземпляр `@kanbaner/plugin-sdk`, а не тот,
  что собран в бандле ядра;
- `mapThrownError` превращал нераспознанную ошибку в безопасный
  `INTERNAL_ERROR`.

Исправление согласовано оркестратором и находится в
`packages/kernel/src/operations/errors.ts`:

- сохранено прежнее поведение для `instanceof PluginOperationError`;
- добавлено структурное распознавание ошибки с `name = "PluginOperationError"`
  и конвертом, прошедшим `PluginErrorSchema` через `validateWithSchema`;
- произвольные `Error` и подделки с невалидным конвертом по-прежнему дают
  `INTERNAL_ERROR` без раскрытия stack/путей/секретов.

Тесты в `packages/kernel/src/operations/bus.test.ts`:

- `распознаёт PluginOperationError из другого экземпляра SDK` →
  `VERSION_CONFLICT`;
- `не принимает подделку с невалидным конвертом ошибки` → `INTERNAL_ERROR`.

UI-часть (`packages/plugin-task-list/src/ui/task-details-panel.tsx`):

- при `VERSION_CONFLICT` устаревшая версия не отправляется повторно;
- форма закрывается, задача и список перечитываются;
- сообщение «Задача уже изменена в другом месте…» хранится отдельно от
  обычной ошибки и остаётся видимым после повторного чтения;
- правка второй вкладки не перезаписывает данные первой.

## Необходимая правка globals.css

В `apps/web/src/app/globals.css` добавлены:

```css
@source "../../../../packages/task-ui/src";
@source "../../../../packages/plugin-task-list/src";
```

Причина: Tailwind автоматически сканирует только `apps/web`, а адаптивные
классы находятся в исходниках пакетов вне этого каталога. Без `@source`
`md:block`, `xl:hidden` и другие классы не попадали в CSS: таблица на
десктопе оставалась скрытой, а мобильная панель перекрывала desktop-интерфейс.
Правка согласована как часть адаптивного UI.

### Evidence VERSION_CONFLICT

E2E-сценарий `не перезаписывает задачу при VERSION_CONFLICT из второй вкладки`:

- вкладка A сохраняет новое название;
- вкладка B отправляет устаревшую версию;
- сервер возвращает `VERSION_CONFLICT` (структурное распознавание в ядре);
- вкладка B показывает «Задача уже изменена в другом месте…», перечитывает
  задачу и отображает правку A;
- название из вкладки B отсутствует в деталях и в списке после reload.

## Риски и ограничения

- Структурное распознавание `PluginOperationError` опирается на публичный
  конверт (`name` + `PluginErrorSchema`). Плагины считаются доверенным
  локальным кодом; посторонний объект с валидным конвертом может быть
  принят за ошибку операции, но не получит доступ к данным.
- `VERSION_CONFLICT` не выполняет автоматический merge: пользователь видит
  объяснение и должен повторить правку на свежих данных.
- Родитель задачи нельзя изменить после создания — ограничение контракта,
  зафиксировано в README и отчёте.
- `@source` привязан к путям пакетов. При переносе `packages/*` потребуется
  обновить директивы; регрессию ловят E2E на 360 px и десктопе.
- E2E выполняется в Chromium с одним worker; пагинация проверяется на
  отображении счётчика, сценарий с 26+ задачами не добавлен.
- Тест `tests/contract/fixture-activation.test.ts` пришлось уточнить из-за
  появления второго встроенного плагина в общем discovery root.
