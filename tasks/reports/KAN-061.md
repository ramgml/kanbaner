# KAN-061 — Компактное представление tool calls

Дата: 2026-11-23. Реализация: worktree
`.worktrees/kan-061-compact-tool-calls`, ветка
`feat/kan-061-compact-tool-calls` от `dev`. Push/merge/rebase не выполнялись.

## Результат

- Добавлен `ToolCallMessage`: нативный `<details>/<summary>` с иконкой статуса,
  именем, подписью состояния и длительностью. Input/output скрыты по умолчанию
  и раскрываются указателем, touch, Enter или Space. Enter/Space обрабатываются
  явно с `preventDefault`, чтобы поведение не зависело от браузера и не
  переключалось дважды.
- Длительность детерминирована: `мс`, `с`, `мин с`; running тикает раз в
  секунду, terminal фиксируется по `endedAt`. Отсутствующие, невалидные и
  обратные timestamps не дают фиктивную длительность. Interval очищается при
  unmount и в StrictMode.
- `mergeToolMessage` объединяет события по `assistantMessageID + tool call ID`,
  сохраняет ранний `startedAt`, первый `endedAt` и непустые input/output/text;
  позднее `running` не понижает terminal status, пустые значения не затирают
  уже полученные.
- `finishToolMessages` завершает running tools только из переданного turn-scoped
  набора identity, сохраняя уже известный `endedAt`. Unconfirmed результат
  tools не завершает, explicit `nonAdmission` завершение не запускает.
- `cancelled` используется как UI-only terminal для Stop, подтверждённой
  отмены, canonical `error.type=aborted` и streaming `session.tool.failed` с
  `error.type=aborted`; обычная ошибка инструмента остаётся `error`.
- Gateway отдаёт только `input`, `output` и timings. History использует
  canonical `time.ran`/`time.completed` с fallback на `time.created` и v1
  `state.time`; stream использует top-level `event.created` как приблизительное
  время до canonical reload. Identity history — v2 `id`/`name` с fallback на v1
  `callID`/`tool`; v1 строковый `state.error`, `state.output`/`state.time`
  нормализуются. `state.metadata`, `part.native` и upstream
  `error.message`/body не передаются, redaction сохранён.
- Длинный неразрывный output переносится внутри `pre` с `overflow-wrap:
anywhere` и не создаёт horizontal overflow панели или документа.
- Группировка последовательных вызовов не реализована: roadmap помечает её как
  опциональную, а минимальный срез требует сохранить отдельные состояния.

## Review-fix

Повод: замечания ревью к `4fb90ff`. Код и тесты доработаны в том же worktree;
push/merge/rebase/amend не выполнялись.

- **HIGH, turn scope.** `finishToolMessages` больше не ищет running tools по всей
  истории. UI ведёт `turnToolsRef` с набором identity, который заполняется в
  `appendTool` для текущего generation, и передаёт этот набор в
  `finishToolMessages`. Confirmed `done`/`cancelled`/`error` завершает только
  tools текущего prompt. Unconfirmed tool предыдущего хода остаётся running и не
  получает ложный `endedAt`; stale generation ничего не меняет.
- **HIGH, nonAdmission.** Явный `nonAdmission: true` не запускает завершение
  tools, потому что prompt не принят. Обычный terminal без `nonAdmission`
  по-прежнему завершает только tools своего хода.
- **HIGH, ручной status check.** `checkTurnStatus` применяет тот же turn-scoped
  набор: canonical `cancelled`/`error` завершает только tools проверяемого
  generation, а unconfirmed tools другого хода не трогает.
- **MEDIUM, streaming aborted.** `session.tool.failed` с
  `data.error.type="aborted"` нормализуется в `cancelled` без generic
  error-подписи и без `output`. Обычная tool error остаётся `error` с
  generic-подписью; upstream `error.message` не раскрывается.
- **LOW, representative v1.** History mapping сохраняет v2 identity
  (`id`/`name`) и получает fallback на реальные v1 `SessionV1.ToolPart`
  (`callID`/`tool`), включая строковый `state.error`, `state.output` и
  `state.time.start/end`. v2 ID не изменился, v1-текст ошибки не утекает.
- **LOW, aria timer.** Тикающая длительность помечена
  `role="timer" aria-live="off"`; статусы остаются доступными, анимация
  длительности не анонсируется каждую секунду. Добавлены assertions.
- **Тесты.** Добавлены регрессии: terminal error/cancelled/done нового хода не
  завершает unconfirmed tool предыдущего; explicit nonAdmission не завершает
  tools; ручная проверка cancelled завершает только tools проверяемого хода;
  streaming aborted → cancelled и обычная ошибка → error; v1 `callID`/`tool`
  со строковой ошибкой; aria-семантика таймера. Обновлены unit-тесты
  `finishToolMessages` на обязательный scope и пустой набор.

## Review-fix 2

Повод: повторное ревью после `1ec5d9a`. Новый маленький fix без
push/merge/rebase/amend.

- **MEDIUM, v1 tool identity.** `messageViews` для `part.type === "tool"`
  выбирает `callID ?? id ?? index`. Реальный `SessionV1.ToolPart` содержит оба
  поля: PartID `id` и tool call identity `callID`; публичный ID теперь строится
  из `callID`. Для v2, где `callID` отсутствует, приоритет `id` сохранён.
  Text part identity по-прежнему использует PartID `id` и не изменена. Оба v1
  fixture содержат разные `id: "part-v1-..."` и `callID: "call-v1-..."`, а
  assertions проверяют публичный ID именно от `callID`. Fallback имени `tool` и
  redaction строкового `state.error` сохранены.
- **LOW, anonymous stream events.** Fallback `tool:optimistic:${Date.now()}`
  заменён на per-turn монотонный
  `tool:anonymous:${turnID}:${generation}:${seq}`. События без `event.id` до
  terminal коррелируются в один anonymous вызов, terminal закрывает его, а
  следующий вызов получает новый ID. Коллизии внутри миллисекунды и между
  ходами исключены; валидный SDK path с `event.id` не изменён и никогда не
  смешивается с anonymous ID. Ограничение: без ID параллельные вызовы
  неразличимы, поэтому поток трактуется последовательно; чужому
  идентифицированному вызову события не присваиваются.
- **Тесты.** Добавлены focused-регрессии: два no-ID вызова в одном ходе не
  сталкиваются и дают две строки; no-ID tool предыдущего хода остаётся running
  после terminal нового хода; v1 `id` + `callID` одновременно, публичный ID от
  `callID`.
