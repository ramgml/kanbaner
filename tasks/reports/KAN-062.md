# KAN-062 — Прокрутка чата без потери позиции чтения

Дата: 2026-11-23. Реализация: worktree
`.worktrees/kan-062-chat-scroll-position`, ветка
`feat/kan-062-chat-scroll-position` от `dev`. Push/merge/rebase не выполнялись.

## Результат

- Follow работает только у нижней границы фактического scroll container: расстояние
  `scrollHeight - scrollTop - clientHeight` не больше 48 px. Порог не зависит от
  последнего сообщения и не использует `scrollIntoView`.
- При чтении выше streaming deltas, upsert tool call, обновление tool status и
  canonical refresh той же сессии не меняют `scrollTop`. Новые сообщения
  учитываются в badge кнопки «К новому сообщению».
- Кнопка возврата находится вне scroll content и является native `<button>`:
  pointer/touch, Enter/Space, `focus-visible`, мобильный layout без hover. После
  возврата к низу кнопка исчезает, follow включается снова, а фокус переносится
  на контейнер с `preventScroll`, поэтому размонтирование кнопки не прокручивает
  ленту.
- Отправка prompt и retry явно вызывают `followNow()`. Смена `session.id`
  сбрасывает unread и открывает конец новой истории; canonical refresh той же
  сессии follow не сбрасывает.
- `ResizeObserver` наблюдает container и content wrapper, window resize и capture
  `load`/`error` работают как fallback. Низ удерживается только в режиме follow;
  раскрытие tool `<details>`, resize панели/textarea, загрузка image preview и
  mobile viewport не двигают позицию читающего выше.
- Контейнер получил `overscroll-contain`, `tabIndex={-1}` и сохранённый
  `aria-live="polite"`. Таймер KAN-061 остаётся `role="timer" aria-live="off"`.
- Виртуализация, IntersectionObserver, новые зависимости и сохранение позиции
  между reload не добавлялись. Generation/abort в scroll-логику не входят.
