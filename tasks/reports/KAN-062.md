# KAN-062 — Прокрутка чата без потери позиции чтения

Дата: 2026-11-23. Реализация: worktree
`.worktrees/kan-062-chat-scroll-position`, ветка
`feat/kan-062-chat-scroll-position` от `dev`. Push/merge/rebase не выполнялись.

## Результат

- Follow работает только у нижней границы фактического scroll container: расстояние
  `scrollHeight - scrollTop - clientHeight` не больше 48 px. Порог не зависит от
  последнего сообщения и не использует `scrollIntoView`.
- При чтении выше streaming deltas, upsert tool call, обновление tool status и
  canonical refresh той же сессии не меняют `scrollTop`. Новые сообщения
  учитываются в badge кнопки «К новому сообщению».
- Кнопка возврата находится вне scroll content и является native `<button>`:
  pointer/touch, Enter/Space, `focus-visible`, мобильный layout без hover. После
  возврата к низу кнопка исчезает, follow включается снова, а фокус переносится
  на контейнер с `preventScroll`, поэтому размонтирование кнопки не прокручивает
  ленту.
- Отправка prompt и retry явно вызывают `followNow()`. Смена `session.id`
  сбрасывает unread и открывает конец новой истории; canonical refresh той же
  сессии follow не сбрасывает.
- `ResizeObserver` наблюдает container и content wrapper, window resize и capture
  `load`/`error` работают как fallback. Низ удерживается только в режиме follow;
  раскрытие tool `<details>`, resize панели/textarea, загрузка image preview и
  mobile viewport не двигают позицию читающего выше.
- Контейнер получил `overscroll-contain`, `tabIndex={-1}` и сохранённый
  `aria-live="polite"`. Таймер KAN-061 остаётся `role="timer" aria-live="off"`.
- Виртуализация, IntersectionObserver, новые зависимости и сохранение позиции
  между reload не добавлялись. Generation/abort в scroll-логику не входят.

## Review-fix после ревью

- HIGH: stale `followingRef` больше не может вернуть вниз. Перед каждой
  автоматической записью `scrollTop` (messages layout effect, ResizeObserver,
  maintain/load/resize fallback) текущий offset сверяется с сохранённой
  предыдущей нижней границей. Уход выше без доставленного scroll event
  выключает follow, показывает кнопку/unread и пропускает запись. Добавлены
  регрессии: silent scroll до delta и после RO callback, затем подтверждающий
  scroll event.
- MEDIUM: unread считается по identity (`chatUnreadIDs`), а не по net length:
  чистое удаление истории не создаёт unread, новые ID и изменённый текст
  считаются. После messages changes и в maintain near-bottom пересчитывается
  даже при `following=false`; если геометрия сама вернула контент к низу, follow
  и badge очищаются без scroll event. Добавлены pure canonical shrink и рост
  `clientHeight` при `scrollTop=0` без synthetic scroll.
- MEDIUM: native scroll anchoring не отключается. Контракт — стабильность
  видимого фрагмента, а не одинаковый числовой `scrollTop` при reflow выше
  viewport. E2E читает середину длинной истории: canonical growth раннего
  сообщения удерживает `boundingClientRect` anchor, hook не делает собственный
  jump; delta без reflow выше viewport сохраняет `scrollTop`.
- LOW: без `ResizeObserver` добавлены capture `toggle` для tool `<details>` и
  window `pointerup`/`keyup` после resize мышью или клавиатурой, с cleanup.
  Тесты проверяют реальный toggle, оба fallback-события и снятие listeners.
  Polling и новые зависимости не добавлялись.
- Прежние session/followNow/keyboard/focus/KAN-060/061 semantics сохранены.

## Ограничения

- Позиция чтения между перезагрузками не сохраняется — это вне среза KAN-062.
- Порог 48 px фиксирован; настройки пользователя для него нет.
- Проверки выполнены на Chromium; другие браузеры и Windows в этом срезе не
  тестировались.
- Без `ResizeObserver` fallback `pointerup`/`keyup` срабатывает уже после
  завершения жеста, а не во время resize; это осознанная деградация без polling.
