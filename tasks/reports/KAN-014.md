### E2E

Добавлен `apps/web/e2e/kanban.spec.ts` — 8 сценариев на production shell:

1. проект, подзадача и задачи в четырёх правильных колонках; поля карточки,
   счётчики, подзадачи, reload, отсутствие overflow;
2. реальный DnD pointer events (`mouse.down/move/up`), затем проверка списка и
   обратного перехода из списка в канбан;
3. клавиатурное меню «В конец», «Выше», «Переместить в Готово» + reload;
4. `VERSION_CONFLICT` из второй вкладки: сообщение, индикатор, откат к
   серверному `done`, задача не потеряна;
5. фильтры project/tag в query string, сохранение после reload, сброс;
6. пагинация колонки: 12 задач при page size 10, порядок без дублей, reload;
7. mobile 360 px: скролл только колонок, overlay `<dialog>`, focus trap,
   Escape и возврат фокуса, gating на `/view/tasks` и `/plugins`,
   breakpoint mobile → desktop → mobile;
8. отключение канбана: маршрут исчезает, задачи и список остаются, включение
   возвращает доску.

## Ограничения и риски

- **Restart процесса в E2E:** Playwright сам владеет lifecycle webServer,
  поэтому сценарий перезапускает не процесс, а страницу (`reload`) и повторно
  читает SQLite. Корректность graceful shutdown/checkpoint проверена отдельным
  `server.shutdown.test.mjs`; для настоящего process restart нужен отдельный
  тестовый harness.
- Позиции уникальны в области `(projectId, status)`. На общей доске без
  фильтра проекта порядок между проектами определяется доменной сортировкой
  `position, id`, а не глобальным индексом колонки.
- Число непосредственных подзадач — отдельный `task.list` с
  `parentTaskId`/`limit: 1` на каждую видимую корневую карточку (N+1).
  Агрегата в контракте задач нет.
- `packages/plugin-kanban` не добавлен в `@source` Tailwind в
  `apps/web/src/app/globals.css` (файл вне владения KAN-014). Структурные
  стили доски и карточек заданы inline; при появлении Tailwind-классов в
  kanban их нужно будет добавить в `@source` отдельной задачей.
- DnD не покрыт jsdom-тестом pointer-геометрии: E2E проверяет реальные
  pointer events в Chromium, component-тесты — состояние и команды.
- Компонентные тесты используют модульное состояние query string; между
  тестами оно сбрасывается `resetKanbanQueryForTests`.
