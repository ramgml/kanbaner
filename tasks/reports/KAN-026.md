## Что сделано

### Форма создания в «Настройках доски»

- В секции «Колонки» модалки добавлена постоянная форма «Новая колонка»:
  название, тип `open` («Обычная») / `done` («Done») и кнопка добавления.
- Создание использует существующую `kanbaner.tasks.column.create` без
  `position`: домен атомарно дописывает колонку в конец порядка.
- Валидация пустого и слишком длинного названия; ошибка не теряет ввод.
- `createGuardRef` и operation token защищают от двойной отправки и от
  снятия pending старой операцией после close/reopen.
- Перед командой и после неё проверяется captured `projectId`/`generation`;
  после смены проекта поздний ответ не мутирует чужой список.
- После успешной команды черновик очищается, выполняется awaited
  `column.list`, новое название получает фокус. Успешный notice показывается
  только после свежего списка.
- Ошибка refresh после успешного create показывает отдельное сообщение:
  «создавать колонку повторно не нужно» и кнопку «Повторить загрузку». Кнопка
  повторяет только чтение `column.list`; мутация не отправляется снова.
- Синхронный `columnsRefreshGuardRef` выставляется до первого await в
  `refreshColumns` и снимается в captured finally только после завершения
  последнего параллельного refresh. Поэтому `requestClose`/`requestDiscard`
  блокируют Escape, backdrop, «Готово», закрытие × и discard на всё время
  retry; поздний ответ применяет список и вызывает `onColumnsChanged`.
- Пока создание или retry загрузки в полёте, модалку нельзя закрыть.
- Пустой список колонок показывает empty state «Пока нет колонок. Создайте
  первую колонку», форма остаётся доступной.
- Черновик новой колонки участвует в dirty-confirm и сохраняется при Escape.
- Форма работает одинаково в канбане и списке, потому что живёт в общем
  `ProjectSettingsButton`.

### Удаление add-column UI с доски

- Из `KanbanView` удалены состояние, guard, обработчики `openAddColumn`,
  `closeAddColumn`, `createColumn`, refs и кнопка `+ Добавить колонку`
  (`kanban-add-column`).
- Из `kanban-column-forms.tsx` удалён неиспользуемый `KanbanAddColumnForm`.
- Удаление, переименование, reorder и тип существующих колонок не менялись.
- При отсутствии колонок настройки остаются единственным путём создания.

## Тесты

### Component / unit

- `project-settings.test.tsx`:
  - создание open/Done с валидацией, append, awaited refresh и уведомлением
    представления;
  - защита от двойной отправки, ошибка без потери ввода и возврат фокуса;
  - ошибка refresh после create: очищенный черновик, сообщение без повторной
    мутации, retry только чтения, отсутствие дубля;
  - deferred retry: Escape, backdrop, × / «Готово» и discard не закрывают
    настройки; после resolve список применяется, `onColumnsChanged` вызывается
    один раз, `column.create` — ровно 1;
  - поздний retry после смены проекта не применяется к чужому списку
    (captured generation);
  - смена проекта/generation во время создания: поздний ответ не обновляет
    чужой список;
  - dirty-confirm и Escape для черновика новой колонки;
  - отсутствие удаления и смены типа существующих колонок.
- `kanban-columns.test.tsx`:
  - `kanban-add-column` больше не рендерится;
  - создание open и Done из настроек, появление колонки и empty state на
    доске;
  - refresh error после create предлагает повторить загрузку, а не создание;
  - прежние сценарии rename/reorder/delete/project switch сохранены.

### E2E (Playwright)

- `kanban.spec.ts`:
  - helper `addColumn` переведён на `project-settings-column-create-*`;
  - создание open и Done из канбана: порядок в конце, empty state обеих
    колонок, persistence после reload;
  - dirty Escape для черновика новой колонки и возврат фокуса после создания;
  - refresh error после create: через route abort серверного вызова
    `column.list`; проверены сообщение, очистка ввода, retry только чтения и
    отсутствие дубля после reload;
  - создание колонки на mobile 360 без горизонтального overflow и persistence;
  - width-тест больше не зависит от фокуса add-column кнопки и проверяет её
    отсутствие;
  - прежние rename/reorder/delete/Done/scroll/swipe сценарии сохранены и
    адаптированы к созданию через настройки.
- `task-list.spec.ts`:
  - создание open и Done из настроек списка, обновление фильтра колонок и
    persistence после reload.

## Ограничения и риски

- Смена проекта во время незавершённого создания покрыта component-тестом, но
  не отдельным E2E: нативная modal-диалог блокирует взаимодействие с
  sidebar/URL во время операции. Проверка generation guard остаётся в
  `project-settings.test.tsx`.
- E2E refresh error моделирует сетевой сбой abort-ом серверного вызова
  `column.list`; контракт команды и запроса не менялся.
- Новых зависимостей, изменений публичных контрактов, схем данных, kernel,
  SDK, storage, task-ui и спецификаций нет.
