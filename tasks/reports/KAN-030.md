# KAN-030 — Цвета проекта и колонок в домене

## Что сделано

- Добавлена фиксированная палитра `BOARD_COLORS`/`BoardColor` и общая
  `BoardColorSchema` в client-safe contract: `default`, `slate`, `blue`,
  `green`, `yellow`, `orange`, `red`, `purple`. Произвольные HEX/CSS-значения
  отклоняются схемой.
- `Project` и `TaskColumn` получили optional `color`; поле хранится внутри
  существующего JSON-документа, SQLite-миграция не требуется.
- `project.create|update` и `column.create` принимают необязательный `color`.
- В `column.update` `title` и `color` необязательны по отдельности, но patch
  без полей отклоняется схемой, а Store дополнительно возвращает
  `INVALID_COLUMN_PATCH`. Color-only update сохраняет заголовок.
- Color-only update с уже сохранённым цветом является идемпотентным no-op:
  Store не повышает версию и не меняет `updatedAt`, activation не публикует
  событие. То же поведение добавлено для color-only `project.update`.
- Прежняя семантика title-only update не изменена: update с тем же заголовком
  по-прежнему повышает версию и публикует `column.updated`/`project.updated`.
- События `column.updated` и `project.updated` содержат `changed` с фактически
  изменёнными полями, включая `color`; отсутствие изменения даёт пустой массив.
- Старые документы без `color` читаются без backfill; `default` остаётся
  оформлением на уровне представления.

`.worktrees/kan-030-board-column-colors-domain`:

  1 файл, 156 тестов — зелёные;

- полный `pnpm check` (format, lint, typecheck, 100 test-файлов / 1434 теста,
  production build Next.js) — exit 0;
- `pnpm check:imports` — границы импортов соблюдены;
- `pnpm test:sqlite` — 1 файл, 1 тест — зелёный.

Командные тесты `color-commands.test.ts` проверяют на обоих provider-ах:

- `project.create`/`column.create` сохраняют `color`;
- color-only update сохраняет `title` (и описание проекта), повышает версию и
  публикует `project.updated`/`column.updated` с `changed: ["color"]`;
- повтор того же цвета не меняет версию, `updatedAt` и не публикует событие
  после коммита;
- устаревший `expectedVersion` при совпадающем цвете даёт `VERSION_CONFLICT`
  до записи;
- пустой `column.update` без `title` и `color` отклоняется JSON-схемой как
  `VALIDATION_ERROR`.

Дополнительно в conformance добавлены проверки: color-only update с новым
цветом повышает версию, с тем же цветом — не повышает и сохраняет `updatedAt`
для проекта и колонки.

## Риски и ограничения

- No-op `column.update`/`project.update` возвращает сгенерированный `eventId`,
  потому что схема выхода требует это поле; событие с таким ID не публикуется.
  Клиентам не следует ждать событие по `eventId` от no-op без изменения полей.
- Отсутствие `color` и явный `default` в домене различаются; эквивалентность
  действует только на уровне представления, как зафиксировано в задаче.
- Ветка не пушилась и не мержилась; интеграция остаётся за оркестратором.
