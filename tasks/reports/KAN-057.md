# KAN-057 — Полный доступ OpenCode для агента kanbaner

Дата: 2026-11-20. Режим: текущий checkout, без worktree, коммита и push.

## Решение пользователя

Пользователь явно выбрал «Полный доступ OpenCode» после обсуждения рисков.
Прежний запрет shell/filesystem для chat-агента `kanbaner` заменён явным
allowlist стандартных инструментов OpenCode. Это не sandbox: агент может читать
и изменять локальные файлы и секреты, выполнять shell с правами пользователя и
обращаться к сети.

Сторонние MCP servers и Code Mode `execute` автоматически не включены. Ручной
Kanbaner MCP allowlist остаётся ограниченным и не содержит delete-инструментов,
но shell/edit способны изменять и удалять локальные файлы вне MCP.

## Результат

- `opencode.jsonc` использует ordered deny `*`, затем явные allow только для
  `question`, `websearch`, `webfetch`, `read`, `glob`, `grep`, `edit`, `shell`,
  `subagent`, `skill`, `external_directory` и `kanbaner_*`.
- `codemode: false` для Kanbaner MCP сохранён. Модели и credentials не
  изменялись; approval flow с `ask` не добавлялся.
- System prompt агента обновлён: полный доступ прямо обозначен как доступ без
  песочницы, с риском для файлов, секретов и сети.
- Catalog содержит 11 built-in OpenCode tools и 14 Kanbaner MCP tools с
  `source: "builtin" | "mcp"`. `operationId` и `requiresExpectedVersion`
  необязательны для built-ins и сохраняются у соответствующих MCP-операций.
- Панель показывает отдельные группы «Встроенные инструменты OpenCode (11)» и
  «Инструменты Kanbaner MCP (14)». Предупреждение «Полный доступ: интернет,
  файлы и shell» находится только внутри раскрытого списка; composer не
  перегружен дополнительным текстом.
- Follow-up: блок модели использует такой же native disclosure, свёрнут по
  умолчанию и показывает текущее имя модели в summary. Controls модели,
  провайдера и варианта раскрываются кликом или Enter/Space; длинные имена
  обрезаются с ellipsis без horizontal overflow.
- Metadata-тест сверяет catalog и ordered permissions с `opencode.jsonc`,
  запрещает wildcard allow, `execute` и сторонние MCP tools.
- Спецификации и README фиксируют решение пользователя от 2026-11-20, границы
  MCP и риски полного доступа.
