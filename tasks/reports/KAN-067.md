## Результат

- Стадия `running` показывает текст `Выполняется` и ровно три заранее
  отрисованные точки. Статическое `…` из `turnPhaseLabel("running")` убрано,
  чтобы не дублировать точки; тексты остальных стадий не изменены.
- Контейнер `RunningEllipsis` — `inline-flex` фиксированной ширины (`w-4`),
  `aria-hidden="true"`, `data-testid="opencode-running-ellipsis"`. Точки
  декоративны, `size-1`, `rounded-full`, `bg-current`.
- Анимация — существующий Tailwind `animate-pulse` с последовательными
  arbitrary-delay классами `0ms/150ms/300ms` и обязательным
  `motion-reduce:animate-none`. Новых зависимостей, keyframes и глобального CSS
  нет.
- React-таймеров нет: текст и состав DOM не меняются во времени, live region
  `role="status"` / `aria-live="polite"` не объявляет кадры.
- Ширина точек постоянна во всех кадрах, поэтому статусная строка не прыгает и
  не расширяет mobile layout.
- `turnPhaseLabel`, retry/unconfirmed/manual status, generation/admission и
  контракты KAN-060–066 не затронуты.

## Риски

- Staggered `animate-pulse` использует arbitrary `animation-delay` классы;
  Tailwind v4 сканирует `packages/opencode/src` через `@source`, поэтому классы
  попадают в production CSS (проверено E2E computed style).
- E2E-сценарий поднимает локальный streaming stub и переадресует prompt через
  `route.continue`; тест не использует скриншоты и не зависит от таймингов
  анимации, только от computed style и доступного статуса.
- Реальный screen reader и браузеры кроме Chromium не проверялись.
