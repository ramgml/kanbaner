# KAN-005 — Шина событий и реестр ресурсов

## Цель

Реализовать публикацию доменных событий, подписки и реестр типов ресурсов, не связывая плагины напрямую.

## Результат

Плагин публикует событие после коммита, другие плагины получают его через подписку, а `ResourceRef` разрешается через зарегистрированный адаптер владельца.

## Объём работ

- [x] Реализовать регистрацию подписок на типы событий.
- [x] Поддержать wildcard в конце сегментов.
- [x] Реализовать публикацию события с единым конвертом.
- [x] Изолировать ошибки подписчиков.
- [x] Журналировать ошибки с `eventId`, `traceId` и plugin ID.
- [x] Не допускать публикацию до явного вызова после коммита.
- [x] Реализовать реестр типов ресурсов.
- [x] Реализовать `resolve`, `canOpen` и `open`.
- [x] Реализовать проверку владельца `ResourceRef`.
- [x] Реализовать операции связей через внедряемый link store.
- [x] Добавить тесты подписок, ошибок и разрешения ресурсов.

## Контракты и зависимости

- Использует `ResourceRef` и метаданные событий из KAN-002.
- Не реализует таблицы связей; получает link store через порт.
- Storage-реализация порта входит в KAN-006.
- Не содержит типов задач или заметок.

## Критерии приёмки

- [x] Подписчик получает опубликованное событие.
- [x] Несовпадающий тип события не вызывает подписчика.
- [x] Wildcard-подписка работает по правилам контракта.
- [x] Ошибка одного подписчика не мешает остальным.
- [x] Подписчик может безопасно обработать повторное событие.
- [x] Событие не публикуется автоматически до коммита.
- [x] `ResourceRef` разрешается только через владельца plugin ID.
- [x] Неизвестный ресурс возвращает `NOT_FOUND`.
- [x] `resolve` не изменяет состояние.
- [x] `link` и `unlink` работают через внедряемый store.
- [x] Удаление ресурса передаётся подписчикам для очистки связей.
- [x] Ошибки содержат стабильные коды.

## Риски

- События начнут использоваться как замена транзакции. Зафиксировать best-effort семантику в коде и тестах.
- Скрытая публикация до коммита. Публикацию вызывает только runtime после успешной операции.
- Реестр станет глобальным изменяемым состоянием. Использовать ограниченный API регистрации.
