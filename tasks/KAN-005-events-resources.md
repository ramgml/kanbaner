# KAN-005 — Шина событий и реестр ресурсов

## Цель

Реализовать публикацию доменных событий, подписки и реестр типов ресурсов, не связывая плагины напрямую.

## Результат

Плагин публикует событие после коммита, другие плагины получают его через подписку, а `ResourceRef` разрешается через зарегистрированный адаптер владельца.

## Объём работ

- [ ] Реализовать регистрацию подписок на типы событий.
- [ ] Поддержать wildcard в конце сегментов.
- [ ] Реализовать публикацию события с единым конвертом.
- [ ] Изолировать ошибки подписчиков.
- [ ] Журналировать ошибки с `eventId`, `traceId` и plugin ID.
- [ ] Не допускать публикацию до явного вызова после коммита.
- [ ] Реализовать реестр типов ресурсов.
- [ ] Реализовать `resolve`, `canOpen` и `open`.
- [ ] Реализовать проверку владельца `ResourceRef`.
- [ ] Реализовать операции связей через внедряемый link store.
- [ ] Добавить тесты подписок, ошибок и разрешения ресурсов.

## Контракты и зависимости

- Использует `ResourceRef` и метаданные событий из KAN-002.
- Не реализует таблицы связей; получает link store через порт.
- Storage-реализация порта входит в KAN-006.
- Не содержит типов задач или заметок.

## Критерии приёмки

- [ ] Подписчик получает опубликованное событие.
- [ ] Несовпадающий тип события не вызывает подписчика.
- [ ] Wildcard-подписка работает по правилам контракта.
- [ ] Ошибка одного подписчика не мешает остальным.
- [ ] Подписчик может безопасно обработать повторное событие.
- [ ] Событие не публикуется автоматически до коммита.
- [ ] `ResourceRef` разрешается только через владельца plugin ID.
- [ ] Неизвестный ресурс возвращает `NOT_FOUND`.
- [ ] `resolve` не изменяет состояние.
- [ ] `link` и `unlink` работают через внедряемый store.
- [ ] Удаление ресурса передаётся подписчикам для очистки связей.
- [ ] Ошибки содержат стабильные коды.
