# @kanbaner/plugin-task-list

UI-плагин адаптивного списка задач Kanbaner. Плагин не владеет данными: он
читает и изменяет задачи только через публичные команды и запросы домена
`kanbaner.tasks`.

## Что делает

- регистрирует представление `/view/tasks`, пункт навигации и панели деталей
  (`app.details`, `app.overlays`);
- показывает таблицу на десктопе и карточки на узких экранах;
- поддерживает фильтры по проекту, статусу, приоритету, тегу и сроку,
  сортировку и пагинацию;
- хранит фильтры, сортировку, страницу и выбранную задачу в query string,
  поэтому состояние переживает перезагрузку и работает как ссылка;
- создаёт проекты и задачи, редактирует, завершает, перемещает и удаляет
  задачи с inline-подтверждением;
- при `VERSION_CONFLICT` не повторяет устаревшую запись, перечитывает задачу и
  показывает объяснение пользователю.

## Границы

- Плагин зависит от `@kanbaner/plugin-sdk`, `@kanbaner/plugin-tasks/contract` и
  `@kanbaner/task-ui`.
- Корневой `@kanbaner/plugin-tasks`, `kernel`, storage provider, драйверы БД и
  внутренности `apps/web` не импортируются.
- Своих таблиц, миграций и кэша у плагина нет. Отключение плагина не удаляет
  задачи и проекты.
- Серверная точка входа (`dist/index.js`) регистрирует только UI-metadata.
  Клиентская точка входа (`dist/ui.js`) импортируется единственным
  composition-модулем `apps/web/src/ui/builtin-ui-plugins.ts`.

## Ограничение: родитель в режиме редактирования

Родительская задача выбирается только при создании задачи. Публичная команда
`task.update` не принимает `parentTaskId`, поэтому в форме редактирования
родитель показан **только для чтения**. Это осознанное ограничение: плагин не
расширяет контракт `kanbaner.tasks` и не эмулирует смену родителя отдельными
командами.

Чтобы изменить родителя, задачу нужно пересоздать; автоматическая миграция
подзадач не выполняется.

## Маршрут и доступность

- Детали загружаются и рендерятся только при `pathname === "/view/tasks"`.
  Прямой `/plugins?task=<id>` не выполняет `task.get`, а client-side переход
  по ссылке в другой раздел сразу скрывает панель.
- Мобильная панель — нативный `<dialog>` с `showModal()`: браузер удерживает
  фокус внутри, Escape закрывает панель, а фокус возвращается на карточку.
  На десктопе modal не открывается (`min-width: 1280px`).
- Shell передаёт текущий `pathname` в публичные props рендерера
  (`UiSlot` → `ContributionRenderer` → `UiRendererProps`), поэтому плагин не
  читает `next/navigation` напрямую.

## Надёжность metadata

- Клиентский реестр проверяет владельца привязанного рендерера до изменения
  состояния и отклоняет чужой pre-bind.
- Повторная синхронизация структурно тех же metadata не увеличивает версию и
  не будит подписчиков.
- Cleanup старого поколения не удаляет вклады, которые уже заменил новый sync.
- При смене `view` на `panel` маршрут удаляется, даже если строка `route`
  осталась прежней.
- Отключение `kanbaner.task-list` не удаляет данные: команды и запросы
  `kanbaner.tasks` остаются доступными через общий composition root. HTTP API
  в текущем MVP ещё отсутствует, поэтому проверка выполняется server-side.

## Проверки

```bash
pnpm --filter @kanbaner/plugin-task-list build
pnpm exec vitest run packages/plugin-task-list packages/task-ui
pnpm --filter @kanbaner/web test:e2e
```

E2E-сценарии списка находятся в `apps/web/e2e/task-list.spec.ts` и работают
против production custom server с изолированным каталогом данных.
