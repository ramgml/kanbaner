# Контекст проекта

Дата фиксации: 2026-11-06.

Kanbaner — локальная однопользовательская система управления задачами и заметками с адаптивным веб-интерфейсом.

Система строится как минимальное plugin-ядро. Задачи, канбан, список, заметки, поиск и интеграции являются плагинами и используют один публичный контракт. Ядро не содержит ИИ: внешние агенты подключаются к HTTP API через необязательный MCP-адаптер. По явному решению пользователя от 2026-11-19 отдельный плагин `@kanbaner/opencode` также предоставляет чат с внешним OpenCode Service; модели, provider credentials и выполнение агента не принадлежат ядру Kanbaner.

2026-11-20 пользователь явно выбрал полный доступ OpenCode для chat-агента `kanbaner` после обсуждения рисков. Прежний запрет shell/filesystem заменён: агенту разрешены стандартные built-in tools OpenCode, включая интернет, файлы, shell, subagent, skill и external_directory. Это расширение прав внешнего агента, а не песочница: возможен доступ к секретам и произвольным файлам, а shell и сетевые инструменты действуют с правами пользователя. Ручной MCP allowlist Kanbaner остаётся ограниченным; сторонние MCP servers и Code Mode `execute` не включены.

## Принятые рамки

- Регистрации и пользовательских аккаунтов нет.
- Приложение предназначено для запуска на localhost или в доверенной локальной сети.
- Основное хранилище — SQLite в режиме WAL.
- Storage backend подключается как провайдер; доменные плагины не зависят от SQLite.
- Внешний сервер БД, Docker и TCP-порт не используются.
- Поддерживаемые ОС MVP: Linux и Windows.
- Плагины считаются доверенным локальным кодом; жёсткая песочница в MVP не предусмотрена.
- Новые функции должны добавляться через Plugin SDK и контракт без изменения ядра.
- MCP не является частью ядра и не содержит доменной логики.
