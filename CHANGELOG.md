## [0.1.0] - 2026-11-26

Первый стабильный релиз Kanbaner. Закрывает оставшиеся MVP gaps после
`0.1.0-rc.0`: отдельный глобальный поиск и универсальный discovery-driven MCP,
а также улучшения OpenCode UX и настроек интерфейса.

**Границы релиза:** новых продуктовых возможностей сверх закрытия MVP gaps нет.
Публикуются только исходники с `pnpm-lock.yaml`, документацией и changelog;
готовых бинарных сборок, npm-пакетов и Docker-образов нет. Требуются Node.js
`24.22.2` и pnpm `12.18.x`.

**Ограничение проверки:** по явному решению пользователя установка, сборка,
нативный `better-sqlite3`, миграции и E2E на Windows в этом релизе не
выполнялись. Обязательными остаются проверки на Linux и в Chromium;
поддержка Windows этим решением не отменяется и требует отдельного
подтверждения в последующих релизах.

**Установка и обновление:** чистая установка выполняется из архива исходников
штатными командами проекта. При обновлении с `0.1.0-rc.0` сначала создайте
online backup через Storage Provider, остановите приложение, установите и
запустите `0.1.0`. Offline restore допускается только на остановленном
приложении и только в новый каталог данных. Автоматический downgrade не
поддерживается.

### Added

- Отдельный глобальный поиск `kanbaner.search`: публичный SearchProvider
  Registry в SDK/kernel, агрегация активных провайдеров, FTS5-индекс SQLite с
  parity для in-memory provider, фильтры по типам, проекту, статусу и тегам,
  bounded pagination, предупреждения о сбоях провайдеров, UI `/view/search`,
  идемпотентная переиндексация и корректный lifecycle при активации и
  деактивации плагинов. Задачи, заметки и fixture регистрируют собственных
  провайдеров; сам поиск не владеет индексом и не читает чужие namespace.
- Универсальный discovery-driven MCP `@kanbaner/mcp` с binary
  `kanbaner-mcp-universal`: строгая конфигурация, перечитывание
  `/api/v1/discovery`, публикация только операций с `exposure.http` и
  `exposure.mcp`, annotations, локальная валидация входа, `expectedVersion`,
  `Idempotency-Key` для поддерживающих mutation, явное разрешение destructive
  операций, redaction секретов и отсутствие доступа к базе данных.
- Глобальный размер шрифта в настройках оформления: 90%, 100%, 110% и 125% с
  сохранением выбора и применением до отрисовки.
- OpenCode UX: стадии prompt и ручная проверка результата без повторной
  отправки, компактные tool calls, сохранение позиции чтения чата, копирование
  блоков кода, черновики по сессиям, история и переименование сессий,
  автоматические названия из первого запроса и анимация статуса выполнения.

### Changed

- Версия приложения и всех private workspace packages синхронизирована с
  `0.1.0`; production built-in plugin manifests также отображают `0.1.0`.
  `kanbaner.projects` зависит от `kanbaner.tasks` `^0.1.0`. Plugin Contract
  остаётся независимым `v1`, Host API — `1.0.0`.
- Поисковый плагин подключён как отдельное рабочее представление и не меняет
  доменные плагины задач и заметок; ручной OpenCode allowlist не расширен
  универсальным MCP.
- OpenCode-панель аккуратнее работает с текущим turn: смена модели, создание
  сессии, переименование и ручная проверка статуса не прерывают уже начатый
  ход и не теряют streamed-сообщения.

### Fixed

- Исправлены гонки подтверждения prompt и ошибочный retry после возможного
  admission; неопределённый результат больше не приводит к повторной отправке.
- Исправлены потеря streamed-текста, неверный счётчик непрочитанных сообщений и
  устаревший кэш истории после ручного terminal outcome.
- Исправлены догрузка и lifecycle глобального поиска, parity фильтров и
  метаданных между SQLite и in-memory provider, а также обработка удалённых
  документов при переиндексации.
- Исправлены сквозные регрессии OpenCode UX: переключение модели и создание
  сессии во время активного turn, сохранение выбранной модели после refresh,
  фокус и клавиатурная доступность, мобильная раскладка и ошибки composer.

### Security

- HTTP API по-прежнему требует Bearer token, внутренний OpenCode UI transport
  использует same-origin проверки и `x-kanbaner-client: ui`, а вложения
  передаются только как проверенные inline `data:` URL. Секреты и настройки
  провайдеров не попадают в браузер.
- Универсальный MCP вызывает только операции, опубликованные одновременно для
  HTTP и MCP, передаёт Bearer token и `x-kanbaner-client: mcp`, запрещает
  redirects, ограничивает timeout и валидирует вход до HTTP-запроса.
  Destructive-операции не экспортируются без явного
  `KANBANER_MCP_ALLOW_DESTRUCTIVE=true`; токены и тела ответов не попадают в
  ошибки. Адаптер не подключается к базе данных.
- Ручной Kanbaner MCP для OpenCode сохраняет прежний ограниченный allowlist из
  14 инструментов и не расширяется автоматически универсальным адаптером.
- По явному решению пользователя chat-агент OpenCode имеет полный стандартный
  доступ к интернету, файлам и shell. Это не песочница: агент может читать и
  изменять локальные файлы и секреты.

### Migrations

- Схема SQLite, инфраструктурные миграции и миграции встроенных плагинов не
  менялись относительно `0.1.0-rc.0`; новых миграций в этом релизе нет.
  Миграции применяются автоматически при bootstrap до активации плагинов, а
  повторный запуск не применяет их заново.
- Порядок обновления с `0.1.0-rc.0`: создать online backup через Storage
  Provider (`.backup()`), остановить приложение, установить и запустить
  `0.1.0`. Offline restore выполняется только при остановленном приложении и
  только в новый каталог данных.
- Откат: запустить предыдущую версию с резервной копией, восстановленной в
  новый каталог данных. Автоматический downgrade не поддерживается. Проверки
  миграций и восстановления на Windows в этом релизе не выполнялись.

## [0.1.0-rc.0] - 2026-11-22

Первый публичный prerelease Kanbaner. Предназначен для проверки текущего
вертикального среза перед стабильным `0.1.0`, а не для заявления о выполненном
Definition of Done MVP.

**Границы среза:** отдельный глобальный поисковый плагин и универсальный
discovery-driven MCP ещё не реализованы. Встроенный поиск заметок, HTTP API,
CLI и ограниченный ручной Kanbaner MCP для OpenCode доступны.

**Ограничение проверки:** по явному решению пользователя этот prerelease
выпускается после полных Linux-проверок, но без новой чистой проверки на
Windows. Windows-установка, нативный `better-sqlite3`, миграции и E2E должны
быть подтверждены перед стабильным релизом.

**Установка и обновление:** публикуются только исходники с `pnpm-lock.yaml`,
документацией и changelog; готовых бинарных сборок, npm-пакетов и Docker-образов
нет. Требуются Node.js `24.22.2` и pnpm `12.18.x`. Для первого релиза обновление
с предыдущего тега отсутствует. При последующих обновлениях сначала создайте
online backup через Storage Provider; восстановление выполняется на остановленном
приложении в новый каталог данных.

### Added

- Минимальное plugin-ядро, публичный SDK, Plugin Contract v1, манифесты,
  зависимости, команды, запросы, события, ResourceRef, UI slots и safe mode.
- Асинхронный Storage Provider на SQLite WAL, namespaced Store-контракты,
  миграции, транзакции, online backup и offline restore.
- Проекты, задачи, подзадачи, приоритеты, сроки, теги и пользовательские колонки.
- Список и канбан с drag-and-drop и клавиатурными альтернативами, массовыми
  действиями, настройками проекта и сохранением порядка карточек.
- Дерево Notion-подобных заметок с визуальным CommonMark/GFM-редактором,
  автосохранением, избранным, поиском, локальными изображениями, связями и
  экспортом самодостаточного Markdown.
- Адаптивный desktop/mobile shell с настраиваемой шириной боковых панелей.
- HTTP API v1 с Bearer token, discovery, command/query transport, ResourceRef,
  `expectedVersion` и `Idempotency-Key`; агентный CLI с доменными сокращениями.
- Необязательная панель OpenCode с выбором модели, streaming, остановкой prompt,
  вложениями, Markdown и previews изображений, включая восстановленную историю.
- Ограниченный ручной Kanbaner MCP для list/get/create/update/complete/move
  проектов, задач и заметок без delete-инструментов.

### Changed

- Основная навигация сосредоточена на рабочих представлениях плагинов; вход в
  обзор и plugin manager находится в настройках.
- Встроенные плагины и private workspace-пакеты синхронизированы с версией
  приложения `0.1.0-rc.0`; Plugin Contract остаётся независимым `v1`, а
  Host API — `1.0.0`.

### Security

- Сервер по умолчанию слушает localhost. Машинный API защищён Bearer token, а
  внутренний OpenCode UI transport — same-origin проверками и
  `x-kanbaner-client: ui`; секреты и provider settings не попадают в браузер.
- OpenCode attachments передаются только как проверенные inline `data:` URL;
  server paths и `file:` URL запрещены. Browser history содержит только
  метаданные, а image preview выдаётся через отдельный guarded binary endpoint.
- По явному решению пользователя chat-агент OpenCode имеет полный стандартный
  доступ к интернету, файлам и shell. Это не песочница: агент может читать и
  изменять локальные файлы и секреты. Ограниченный Kanbaner MCP не расширяет
  эти права автоматически.

### Migrations

- Схема SQLite и миграции встроенных плагинов применяются автоматически при
  bootstrap до активации плагинов; повторный запуск не должен применять их заново.
- Перед будущими несовместимыми миграциями требуется резервная копия. Откат
  выполняется запуском предыдущей версии с восстановленной копией в новом
  каталоге данных; автоматический downgrade не поддерживается.
